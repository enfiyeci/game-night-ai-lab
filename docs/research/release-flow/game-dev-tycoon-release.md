# Game Dev Tycoon (Greenheart Games, 2012/2013): the release sequence, screen by screen

Scope note: this covers the base game as currently sold on Steam (the wiki's version-tagged
pages mostly describe v1.3.9–1.4.4; the core release/review/sales loop described here has not
changed in later patches per any source found, but individual number tables may be superseded by
newer versions — flagged where relevant). "Ticks" below are the small square markers next to the
in-game week counter; a "week" is the game's basic time unit.

## Step-by-step account (chronological, synthesized from the findings below)

1. **Naming happens before development, not at release.** The game's title is typed in during
   pre-production, before Stage 1 starts — one of the choices made alongside Size, Topic, Genre,
   Platform, Audience and Engine. It cannot be edited once development is underway. There is a
   "Writer's Block" achievement for leaving the name blank for a while, which confirms naming is
   a distinct, skippable-for-a-moment text-entry step at project creation, not a forced modal.
2. **During development**, the player drags 9 time-allocation sliders across 3 stages, watches
   "Design" (orange) and "Tech" (blue) point-bubbles fly up to two counters, and manages bugs.
   None of this is the release moment itself, but it is what the release moment scores.
3. **When development finishes**, the game presents exactly two choices: **Release** or
   **Cancel** — confirmed by a Greenheart Games forum thread titled literally "Why is there no
   option to delay a game, only release or cancel?" (2015). There is no dedicated "delay"
   button. Players report an unofficial workaround: leave the finished game sitting un-released;
   this does not add more points ("orbs approach zero after a few weeks") and hype visibly drains
   while it sits, so waiting is a bad trade, not a real delay mechanic.
4. **Clicking Release publishes the game immediately** — the wiki's plain description is "After
   a game is completed (as the player sees fit), they are able to publish the game for points on
   leveling up engine parts and players, and get reviews." No further confirmation dialog is
   documented in any source read.
5. **A ding sound plays when a game is completed** (a critic singled this out as the game's best
   moment: "The satisfying 'ding' that sounds when a game is complete" — gamecritics.com, 2014).
6. **Reviews arrive 3 ticks after publishing**, per a notification: "a notification appears 3
   ticks (little squares next to the week) after to tell you that first reviews are out."
7. **Four named review outlets** each produce a score and a one-line quip: **Star Games,
   Informed Gamer (parodying Game Informer), Game Hero (likely GameRevolution) and All Games**.
   Only one true score is computed internally; the four displayed numbers are that score run
   through a small per-reviewer randomizer (see below), so the four scores cluster near each
   other but are rarely identical.
8. **The review score is computed by comparing the game to the player's own best-ever game**,
   not to any absolute quality bar — full mechanics in the Review-score question below.
9. **After reviews, sales begin.** The wiki's Sales Algorithm page describes this as three
   phases (estimate market size → compute total lifetime sales → spread that total over weekly
   installments); a game "is taken off the market when its total revenue is greater than [the
   computed total], or if a week's income rounds to zero."
10. **A "Game Report" becomes available after a release's reviews land**, giving text-only
    insights about that Topic/Genre (and other) combination ("Racing and Action are a great
    match") — no chart, on demand, one per combination the player has actually tried.
11. **Marketing and hype are built before release, not after**: G3 (the annual expo, a parody of
    E3) prompts a booth-purchase popup once a year at M5 W1 for an event at M6 W2; marketing
    campaigns and hype from sequels/being invited to G3 all accumulate into a hype score that is
    read at the moment of release and multiplies day-one/early sales.
12. **No Hall of Fame, no "game of the year" ceremony, no top-sellers chart exists in the base
    game** (unlike Kairosoft's Game Dev Story, which GDT was inspired by and which does have a
    Hall of Fame/Game Awards — do not conflate the two; early search results kept surfacing the
    wrong game's wiki). GDT's only persistent per-game record is the Game History tab (name,
    platform, genre/topic, sales, cost, profit, score, fans, top-sales rank) and a fixed
    achievement list (sales-copy milestones: Gold/Platinum/Diamond/Unobtainium at 500K/1M/10M/100M
    copies; "Perfect Game" for a clean 10; "Versatile" for a hit in each of the five main genres).

## Key question: When development ends, what happens? Naming, release button, confirmation, delay/cancel

### Takeaway
Naming is locked in during pre-production, before Stage 1 begins, and cannot be edited during
development; the finished-game screen offers only two buttons, Release or Cancel, with no
official delay option, and clicking Release appears to publish immediately with no further
confirmation step documented anywhere found.

### Cited Findings
- "After a game is completed (as the player sees fit), they are able to publish the game for
  points on leveling up engine parts and players, and get reviews." — [Game Dev Tycoon wiki, main
  page](https://gamedevtycoon.fandom.com/wiki/Game_Dev_Tycoon) (read in full)
- Pre-production choices, listed in order, include "Game Title. The game's name." alongside Size,
  Target Audience, Topic, Genre, Platform and Game Engine — all pre-production, i.e. before
  development starts — [Game Development/1.3.9 wiki page](https://gamedevtycoon.fandom.com/wiki/Game_Development/1.3.9) (read in full)
- Achievement "Writer's Block: Naming games is sometimes difficult," unlocked by "Don't name your
  game for a minute" — confirming naming is a live text-entry step at project creation that can be
  left blank briefly — [Achievements wiki page](https://gamedevtycoon.fandom.com/wiki/Achievements) (read in full)
- A Greenheart Games forum thread titled "Why is there no option to delay a game, only release or
  cancel?" (Oct 2015) — the original poster explicitly frames the choice as binary: "the only
  other option when you know you're looking at a solid 6.25 is to scrap the game completely." A
  reply (chizbejoe) confirms the unofficial workaround: "You can delay it by just not releasing it
  until you have the amount of points you want. It's not perfect, but it sorta works" — followed by
  another reply noting hype drops while waiting, and 20 days later CSDragon reporting "the number
  of orbs you get quickly approaches zero after just a few weeks of sitting on the game." —
  [Greenheart Games forum thread](https://forum.greenheartgames.com/t/why-is-there-no-option-to-delay-a-game-only-release-or-cancel/19210) (read in full)
- A WebSearch-summarized Steam thread and Greenheart forum thread ("Post-Development Name Change")
  indicate you can rename a game "when the experience screen appears upon release ... by clicking
  on the notepad icon on the right of the game's name," and that the game's name has no effect on
  ratings. ⚠️ This claim rests only on a WebSearch tool summary; the underlying forum thread at
  forum.greenheartgames.com could not be reached directly (site returned a "read only mode" banner
  for one thread but this specific one was not opened) — treat the notepad-icon/post-release-rename
  detail as unverified until traced to the primary thread.
- Sales algorithm math (below) explicitly gates on review score and hype "at the time of release,"
  implying release is a single, immediate, dated event rather than a soft/gradual rollout —
  [Sales Algorithm wiki page](https://gamedevtycoon.fandom.com/wiki/Sales_Algorithm) (read in full)

### Inferences
- Because Cancel exists as a real alternative to Release (per the forum thread's framing) and
  because the wiki phrases release as happening "as the player sees fit," a finished game is not
  auto-published — the player must click Release, but nothing in any source describes an
  additional confirmation dialog (e.g., "Are you sure?") after that click. Absence of such a
  dialog in every walkthrough-style description read is suggestive but not proof it doesn't exist.
- No source states whether "Cancel" recovers any of the money/time spent; this was not the focus
  of any source found and should be treated as unknown.

### Gaps
- No source was found that names the exact UI copy on the Release/Cancel screen, or confirms/
  denies a confirmation dialog after clicking Release.
- The "notepad icon to rename post-release" detail is sourced only via a WebSearch summary, not a
  directly read page (⚠️ see above) — worth a direct check before relying on it for design
  decisions.

## Key question: The review-score reveal — reviewer count, presentation, scale, computation

### Takeaway
Exactly four outlets (Star Games, Informed Gamer, Game Hero, All Games) each show a score and a
short quip on a 1–10 scale; only one underlying score is computed per game, and that single score
is what gets nudged per-reviewer by a small randomizer before display. The underlying computation
compares the game's quality-adjusted point total against the player's own historical best (not an
absolute bar), factoring in tech/design balance, topic/genre "combo" fit, platform/genre fit,
audience/topic fit, bug ratio, and a "trend" bonus/penalty — with post-processing passes that
artificially suppress a player's first couple of high scores early in a save.

### Cited Findings
- "Four publications rate the player's games after they are finished... The publications are Star
  Games, Informed Gamer (Game Informer), Game Hero (possibly GameRevolution), and All Games." —
  [Publications wiki page](https://gamedevtycoon.fandom.com/wiki/Publications) (read in full)
- "When you publish a new game, a notification appears 3 ticks (little squares next to the week)
  after to tell you that first reviews are out." — [Review Algorithm/1.4.4 wiki page](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4) (read in full)
- "Only one score is generated for a game. Then an artificial transformation is applied to get the
  four scores you can see on the review screen." — same source
- Score generation per reviewer: "A random value is added to the score. It can be: 0 (50% chance),
  1 (25% chance), -1 (25% chance). However, if the score is 5 or 6... 2 (1.25%), -2 (1.25%)...
  Score is then clamped between 1 and 10." A special rule: if the 4th generated score would be a
  10 after three prior 10s, but a perfect score is not technically reachable for that game (see
  Technical Expertise below), it is forced down to 9. — same source
- Each reviewer score also carries a short text quip drawn from one of three message pools (good,
  bad, standard), chosen based on that reviewer's rolled score (>2: good/standard chance; <6:
  bad/standard chance) — same source
- Underlying score math, in order: (a) **Technical expertise factor** caps the maximum possible
  score based on game size and, for AAA games, the number of assigned specialists — e.g. Small/
  low-fan Medium games cap at 9 (never a perfect 10 across all four categories); (b) a **Target
  Game Score (TGS)** is computed from the player's Top Score, a "Top Score Delta," and a
  year-based modifier (1.15 before year 6, 1.2 from 6–23, 1.1 after) — i.e., **the bar to beat is
  the player's own best previous game, not a fixed standard**; (c) a **quality factor q** starts
  at 1 and is adjusted for: Tech/Design balance vs. the genre's ideal ratio (±0.1), slider-time
  allocation vs. design-focus rules (±0.1 to ±0.2, scaled up for MMOs), topic/genre "combination"
  messages (Great/Strange), sequel/engine-reuse penalties, and an MMO topic/genre penalty; (d) a
  **bug ratio** (1 if no bugs; otherwise reduced based on bug count relative to Tech+Design); (e) a
  **trend factor** (1.2 for matching a genre/topic/audience trend, or a scaled bonus/penalty
  0.85–1.4 specifically for "Strange Combo" trends); (f) topic/genre and topic/audience combination
  values also apply a **direct score penalty** as of v1.44 if the score/TGS ratio is ≥0.6 and the
  combination value is ≤0.7 ("you lose half your score above 6"), plus a platform/genre penalty
  applied per-platform. All these combine into a raw game score `g`, which is then divided by TGS
  and scaled by the technical-expertise factor to get a provisional review score. — same source
- **Post-treatment ("first pass")**: if the provisional score is ≥9 and either the quality factor
  is below 1.1 (80% chance it fires) or an inexperienced staff member contributed, the score is
  forcibly re-rolled down into either [8.45, 9.1] (75% chance) or [9, 9.25] (25% chance). —
  same source
- **Post-treatment ("second pass")**, only before in-game Year 4 and only if the player has fewer
  than 2 prior "high score" games: a perfect 10 becomes a random value in [8.5, 8.95]; a 9–10 score
  is reduced by [1.05, 1.25]; an 8.5–9 score is reduced by [0.4, 0.6] and no longer counts as a
  high score. If the resulting score is the player's exact third high-score game, it is arbitrarily
  set to 10. — same source. This mechanic exists specifically to prevent new players from getting
  suspiciously good scores immediately.
- Design intent / player-facing effect, from a third-party review: "Good quality game DOES NOT
  MEAN good reviews... you compete exclusively against your own previous high score... in order to
  keep getting good review scores every time, you need to be consistent, not good." —
  [Game Development/1.3.9 wiki page](https://gamedevtycoon.fandom.com/wiki/Game_Development/1.3.9) (read in full)
- Reception of the review screen from a professional review (3/10, gamecritics.com, 2014): "The
  reviews don't help either, since only short quips like 'Fun' or 'Falls a bit short' are all that
  are given." The review's "HIGH" callout: "The satisfying 'ding' that sounds when a game is
  complete." — [gamecritics.com review](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/) (read in full, including reader comments)
- A WebSearch summary (not independently verified against a full page) describes the review popup
  as functioning "much like a modified slot machine," cycling through the four scores, with the
  design/tech point-bubbles flying up the screen during development (not during the review reveal
  itself) as the game's main animated feedback, and only "notification beeps... bloops... laid
  back elevator style music" for audio. ⚠️ This is a WebSearch tool synthesis of several review
  snippets (gamecritics.com plus others), not a page read end-to-end by me for this specific claim
  — treat the "slot machine," "cycling," and "sequential reveal" framing as directionally likely
  but unconfirmed by a primary source read in full.

### Inferences
- Because only one true score is generated and the four displayed scores are that score plus a
  small independent random nudge per reviewer (not four independently-modeled critics), the
  "outlets" are cosmetic/flavor rather than a genuine simulated press — worth knowing if borrowing
  the "multiple reviewers" beat: the tension is manufactured by variance, not by genuinely
  differing critical takes.
- The post-treatment passes (especially the "second pass" before Year 4) function as a soft
  tutorialization/anti-frustration system: they suppress suspiciously good early scores so a new
  player's first few games don't feel undeservedly perfect, then loosen once the player has proven
  they can hit ≥9 three times.

### Gaps
- No source directly confirms whether the four scores appear on screen simultaneously or reveal
  one-by-one with a pause/animation between each (the "slot machine" description is second-hand
  via WebSearch, not a primary source read in full).
- No source specifies the exact visual layout of the review popup (logos, order of outlets, score
  font/color coding) — only that it is a popup, distinct from the Game History tab.
- No confirmed detail on whether there is a distinct sound per score reveal versus a single
  chime — only the "ding on completion" (pre-review) and general "notification beeps" during
  development were sourced.

## Key question: Sales follow-up — weekly numbers, graph, notification feed, fans, market lifespan

### Takeaway
Sales are computed algorithmically as a single lifetime total at the moment of release (based on
market size, review score, hype, and publisher/fan status), then paid out in weekly installments
that taper off; a game is pulled from the market once its cumulative revenue passes that computed
total or a week's income rounds to zero. No source found describes a persistent on-screen sales
graph or chart in the base game; the durable record is the Game History tab (from the sibling
research file, not re-verified in this session — see note).

### Cited Findings
- Sales computation is explicitly staged: "(1) Estimating the market size (2) Calculating total
  sales amount (3) Breaking it down in subsequent weeks." — [Sales Algorithm wiki page](https://gamedevtycoon.fandom.com/wiki/Sales_Algorithm) (read in full)
- Market size is read off a platform's install-base curve at the current in-game date (linear
  interpolation between two known data points), then scaled to a "useful market size" M using a
  per-platform/genre sales modifier.
- Total lifetime sales (before hype) are computed from the review score R via a market-reach curve
  U (cubic below 9, steeper above 9, reflecting that scores above 9 sell disproportionately more),
  modulated by an office-tier/date-based multiplier L (bigger bonus at R≥9 once in the 4th office;
  penalty at R<9 especially before the 4th office).
- **Hype effect on sales is explicit and capped**: hype factor h = (hype points at release)/500,
  capped at 1. If R≥5, sales increase by up to 5% of market size scaled by how far above 5 the
  score is and by hype; if R≤5, sales are further reduced, again scaled by hype — so hype amplifies
  good scores and (mechanically) also amplifies the penalty of bad ones. Absolute cap: sales can
  never exceed the total addressable market M.
- **Fan gain per release**: if R≥7 (and not a too-recent sequel), the fanbase grows 5–10% just from
  releasing; further gains scale with market size, review score, and whether the game is
  externally published vs. self-published; scores ≤5 (or a too-recent sequel) instead *shrink* the
  fanbase, proportional to how far below 10 the score is.
- **Market exit condition, verbatim**: "The C value defined previously is then distributed over the
  course of several weeks, and the game is taken off the market when its total revenue is greater
  than C." Later: "If I' = 0 then the game is taken off the market" (I' being that week's net
  income after royalty rate). — same source
- Weekly income tapers via a piecewise formula keyed to how much of the lifetime total C is still
  unsold — the closer a game gets to its computed lifetime total, the smaller each week's income,
  which is what produces the natural decline-and-drop-off curve rather than a hard weekly
  countdown.
- Indirect evidence of an on-screen weekly sales popup: a GitHub issue for a community mod
  ("InfoStatsMod") is titled "sales pop up out of screen," implying the base game does show some
  kind of sales pop-up notification that the mod's extra UI can visually collide with. ⚠️ This is
  inferred from a bug-report title only, not from a page or the mod's own documentation read in
  full — treat as a weak signal that a sales notification popup exists, not confirmation of its
  content or frequency.

### Inferences
- Because the payout curve is "front-loaded and tapering" (the raw-income formula pays out a
  larger fraction of what's left when a lot is still unsold, and a smaller fraction as the game
  nears its computed total), the felt shape in-game is almost certainly "big first week(s), then a
  long tail," matching how conventional sales-decay curves are usually depicted — but this is my
  inference from the formulas, not a directly cited description of the player-visible curve shape.
- There is no evidence anywhere in the sources gathered of a fixed "weeks on shelf" number — market
  exit is entirely a function of when cumulative revenue catches up to the pre-computed lifetime
  total, which varies game to game and can't be predicted by the player without either modding or
  extensive play experience.

### Gaps
- No primary source (read in full) describes the actual on-screen sales feed/notification UI —
  only the underlying math and one indirect (bug-title) hint that a popup exists.
- Typical or average "weeks on the market" figures were not found in any source and would need
  either community datamining or direct play-testing to establish.
- The prior repo research file `docs/research/game-dev-tycoon/secondary-screens-2026-09-25.md`
  states as its own ⚠️-flagged item: "Hype and fans: next to a game in development or on sale... no
  source described the actual widget, so whether it is an always-on counter or on-demand is
  unconfirmed." This session did not resolve that gap either — it is carried forward, not newly
  verified.

## Key question: The Game Report — when it appears, what it contains, how it teaches

### Takeaway
The Game Report is a menu-accessible (not automatically popped-up), text-only feedback screen that
appears once a Topic/Genre (or other) combination has actually been tried and reviewed; it gives
qualitative, rule-of-thumb-style hints ("Racing and Action are a great match") rather than any
chart or number, and its stated purpose is to let players piece together which combinations work
by trial rather than by being told the underlying formula.

### Cited Findings
- "The 'Game reports' mechanic was introduced in version 1.4.0 (August 20, 2013), the first Steam
  release" — WebSearch summary citing the Greenheart Games changelog. ⚠️ The changelog page itself
  was not opened and read directly in this session; this date is taken from a WebSearch synthesis,
  not verified end-to-end.
- "The game is intended for you to use your intuition and then generate a game report to see what
  worked well and what didn't — slowly piecing together the data." — WebSearch summary of Steam
  community guide content; ⚠️ not read from the primary guide page directly in this session.
  same caveat applies.
- Direct player-facing example of report phrasing, from a professional review: "the only tool
  offered is post-sales research, but it doesn't specifically say what gameplay elements to devote
  more or less time to, and instead offers 'Racing and Action are a great match' or some other rote
  observations." — [gamecritics.com review](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/) (read in full)
- The sibling repo file `docs/research/game-dev-tycoon/secondary-screens-2026-09-25.md` (a prior
  research subagent's work, not re-verified line-by-line by me in this session) states: "Game
  report | After a release's reviews | Text insights ('Racing and Action are a great match') for
  combinations already tried; no chart | From game 1 | On demand, per game." This matches the
  gamecritics quote above, which is independently and directly sourced in this session, giving two
  independent confirmations of the "no chart, text insight only" characterization.

### Inferences
- Because the Game Report only speaks to combinations "already tried" (per the inherited note) and
  the review-score algorithm computes topic/genre "combo" quality as a hidden 0.6–1.0 multiplier
  the player never sees directly (per the Review Algorithm page read in full this session), the
  Game Report functions as the game's only sanctioned way to partially reverse-engineer that
  hidden table — it teaches by confirming or denying combinations after the fact, not by
  predicting them in advance.

### Gaps
- The exact wording/breadth of Game Report content beyond the one quoted example ("Racing and
  Action are a great match") was not found in any source read in full this session — a fuller
  catalogue of report phrasings would need either a Let's Play transcript or direct play-testing.
- Whether the Game Report also surfaces platform/genre or platform/audience fit (not just topic/
  genre) was not confirmed by any source read in full.

## Key question: Marketing/hype before release, conventions (G3), pre-release decisions

### Takeaway
Hype is a single accumulating number, capped in its sales effect at "500+ points," built mainly
through the annual G3 convention (a parody of E3) and, once researched, a self-hosted convention;
G3 itself is a two-stage yearly event — a booth-purchase popup at M5 W1, gated by fan count into
Small/Medium/Large tiers costing $80K/$500K/$1.5M, followed by the actual convention at M6 W2 that
converts booth size and visitor count (driven by fans) into a hype boost for whatever game is
currently in development.

### Cited Findings
- "Conventions are annual events that boost the hype of whatever game you have in development,
  also they increase the sale of any 'MMO's or 'Console's you have on sale." — [Convention wiki
  page](https://gamedevtycoon.fandom.com/wiki/Convention) (read in full)
- "G3... is an annual event. Each year at the beginning of M5 W1, you will be prompted to purchase
  a booth for the convention which will occur at the beginning of M6 W2... The booths are priced at
  80K, 500K, or 1.5M for small, medium, or large booths respectively... if you do not have enough
  money that year to attend or simply don't want to, simply click the 'X' on the top right-hand
  corner to exit the pop-up. There are no known penalties other than losing potential hype." —
  same source. Booth-size gating by fan count: Small <40,000 fans; Medium 40,000–100,000; Large
  >100,000.
- "Running your own convention is a research option in the R&D lab... A custom convention replaces
  G3." — same source (this refines the sibling note's characterization of the two conventions as
  simply additive; per this directly-read page, the self-hosted convention *replaces* G3 rather
  than stacking with it, which conflicts with a WebSearch-summarized claim below).
- ⚠️ Conflicting claim, not independently verified: a WebSearch summary states "You get your own
  convention in addition to G3 rather than instead of it, so it's essentially double the hype/fan
  gain." This directly contradicts the Convention wiki page's own sentence "A custom convention
  replaces G3," which I read in full. Given the direct page read takes precedence over a
  WebSearch synthesis, treat "replaces G3" as the better-sourced claim, and the "stacks with G3"
  claim as an unresolved conflict worth flagging rather than silently picking one.
- Hype mechanics (formula-level): hype factor h = (accumulated hype points at moment of release) /
  500, capped at 1; this h multiplies a sales bonus (if review score ≥5) or amplifies a sales
  penalty (if review score ≤5) at the moment sales are computed — i.e., **hype is "cashed in"
  exactly once, at release**, not spent gradually during the sale period. —
  [Sales Algorithm wiki page](https://gamedevtycoon.fandom.com/wiki/Sales_Algorithm) (read in full)
- Marketing campaigns (a separate lever from conventions) are unlocked at Year 4 Month 5 Week 2,
  and the recommended pattern from a community strategy source is "a 500K Campaign at the
  beginning of Stage 2, then a 50K Campaign every now and then to get immediate increases in hype
  by several dozen." ⚠️ This is a WebSearch summary of wiki/guide content, not a page read in full
  by me this session.
- Reddit/Steam-thread consensus (from the sibling repo note `secondary-screens-2026-09-25.md`,
  itself citing Steam thread 864977564147885621 "How does the Hype works?"): "The best way to get
  a lot of hype is to make sure you get the invite for G3... during the development of the game" —
  this is the inherited note's paraphrase, not re-verified directly by me this session.

### Inferences
- Because hype is capped at a fixed denominator (500 points) and cashed in exactly once at
  release, the game's marketing design intentionally makes hype a "pre-release-only" lever rather
  than something that can rescue a game after a weak launch — matching a broader pattern already
  observed in the sibling office-progression note that other GDT systems (staff caps, room
  unlocks) also gate progress by hard, legible thresholds rather than soft curves.

### Gaps
- The direct conflict between "custom convention replaces G3" (page read in full) and "custom
  convention stacks with G3" (WebSearch summary) was not resolved in this session — a design
  decision that depends on this fact should re-check the primary wiki source (which is the better
  of the two) or, ideally, the current in-game tooltip.
- No source describes a pre-release "hype meter" widget's on-screen appearance (bar? number?
  always visible vs. on demand?) — this matches the same gap already flagged in the sibling
  secondary-screens note and remains unresolved.

## Key question: Milestones / first-time moments, Hall of Fame, top-selling games

### Takeaway
Game Dev Tycoon has no Hall of Fame, no Game-of-the-Year ceremony, and no yearly top-sellers
chart — those are features of Kairosoft's Game Dev Story (the game GDT was explicitly inspired
by/parodying), and multiple search results conflated the two during this research; care was taken
to discard Kairosoft-wiki content that surfaced by mistake. GDT's actual persistent milestones are
a fixed achievement list (mostly sales-copy thresholds and one-off "perfect game"/"versatile"
awards) plus the Game History tab as a running record — there is no dedicated "first game
released" fanfare beyond the review/sales flow itself.

### Cited Findings
- "Game Dev Tycoon was inspired by the iOS and Android game, Game Dev Story by Kairosoft." —
  [Game Dev Tycoon wiki, main page](https://gamedevtycoon.fandom.com/wiki/Game_Dev_Tycoon) (read
  in full) — explicit confirmation the two are different games, used here to justify discarding

- Given no source (Kairosoft confusion aside) mentions any special first-release fanfare, and the

  most likely reading is that GDT deliberately treats the first release the same as any other —
  the "achievement" framing (Gold/Platinum/etc.) is the only mechanism that marks a milestone, and
  those are all about cumulative sales, not "first time" events.
