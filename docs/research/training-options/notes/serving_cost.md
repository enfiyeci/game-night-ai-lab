# Frontier Model Training Options — The Real Cost of Running (Serving) a Model, Pricing, and Naming

Research date: 2026-09-25. All figures dated; leaked/self-reported/estimated figures are labeled as such.

## What drives inference cost: architecture, attention, quantization, batching, hardware, reasoning tokens

### Takeaway
Serving cost per token is set mainly by how many parameters are *active* per forward pass (compute/FLOPs) versus how many parameters exist in *total* (memory footprint), by how big the KV cache (the per-request memory that stores past attention keys/values so the model doesn't recompute them) grows with context length and concurrent users, and by how much of the GPU fleet is kept busy (batching/utilization). Mixture-of-Experts (MoE) architectures decouple these two by activating only a subset of experts per token, cutting compute cost relative to a dense model of the same total size, but total-parameter memory and KV-cache costs still track something closer to the full model. Newer GPU generations (H100 → B200) and lower-precision math (FP8/FP4 quantization) then multiply on top of the architecture choice, and "reasoning" models multiply again by generating many more output tokens per answer.

### Cited Findings
- In MoE models, "cost tracks active parameters for compute (FLOPs), while on disk and in memory, cost tracks total parameters" — [Epoch AI, MoE vs Dense Models: How do they compare in inference?](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- For GPT-4 (widely believed to be a ~1.8 trillion-parameter MoE), Epoch AI's analysis estimates its arithmetic (compute) cost is equivalent to a ~275B-parameter dense model, but its network-communication cost is equivalent to a ~635B-parameter dense model, and in the fast/short-context decoding regime its "dense-equivalent size" rises to roughly 950B parameters — because at that stage memory movement, not raw compute, dominates cost — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- General formula given by Epoch AI for MoE "dense-equivalent" decoding cost: divide total parameters by (number of experts)^0.44 / (active experts)^0.63; for Mixtral 8x22B (140B total params) this gives roughly a 90B-dense-parameter equivalent in fast decoding — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- "MoEs are more efficient at inference than dense models of the same total parameter count, but less efficient than dense models with the same active parameter count" — an 8-way sparse MoE has roughly the short-context decoding economics of a dense model half its size — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- On H100 GPUs, once batch size passes roughly 300 tokens (the "critical batch size"), memory-movement time starts to exceed arithmetic time, which erodes MoE's active-parameter cost advantage — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- KV-cache memory grows with both context length and the number of concurrent requests; each request holds a cache proportional to context length, so long-context use limits how many requests can be served concurrently (batched) on given hardware — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- MoE models can end up cheaper than dense models at long context specifically because attention arithmetic cost *and* KV-cache read cost both scale with the number of attention heads, and MoE designs (e.g., GPT-4's attention dimensions reportedly resemble GPT-3's 55B-parameter attention block despite GPT-4 being ~10x larger overall) can keep attention/KV-cache small relative to total size — an MoE with 16 experts could be roughly 60% cheaper to serve than an equally large dense model under optimized grouped-query attention — [Epoch AI](https://epoch.ai/gradient-updates/moe-vs-dense-models-inference)
- DeepSeek V3.1 (open-weight, 671B total parameters) activates only ~37B parameters per token in a single forward pass, but that active-parameter count "grows nearly linearly with batch size" because different queries in a batch route to different experts — at large enough batch sizes the serving system may need to load close to the full 671B-parameter model into memory — [Introl, Inference Unit Economics: The True Cost Per Million Tokens](https://introl.com/blog/inference-unit-economics-true-cost-per-million-tokens-guide) (⚠️ this specific claim is quoted from a WebSearch-generated summary of the Introl blog post; the underlying page itself was not separately opened/read in full in this session — treat as secondary until verified against the primary post)
- Nvidia B200 (Blackwell generation) delivers roughly 6x the throughput of H100 at a modest hourly price premium, translating to lower cost per token; one comparison cites B200 at ~$0.02 per million tokens versus ~$0.14 on H100 (a ~7x reduction) for a given workload — [GMI Cloud / cited via search summary of "NVIDIA GPU Cloud Pricing by Model"](https://www.gmicloud.ai/en/blog/nvidia-gpu-cloud-pricing-by-model) (⚠️ read only via search-result summary, not fetched in full — treat as a secondary/aggregator claim)
- SemiAnalysis's InferenceX tool reports, for the open-weight gpt-oss-120B model at 166 tokens/sec/user, B200 costs $0.04 per million tokens versus $0.26 on H100 for the same throughput target — [SemiAnalysis InferenceX](https://inferencex.semianalysis.com/compare-per-dollar/gptoss-120b-b200-vs-h100) (⚠️ seen only via search-result summary in this session, not fetched directly)
- For a 70B dense model at FP8 precision under continuous batching, one estimate puts B200 at ~$0.82 per million tokens versus ~$1.04 on H100 — a more modest gap than the MoE/throughput-optimized cases above, because dense model serving is less able to exploit Blackwell's low-precision (FP4) and NVLink-72 advantages without model-specific optimization — [Digiteria Labs, "NVIDIA B200 Pricing: 40% Cost-Per-Token Cut vs H100"](https://digiterialabs.com/ai/insights/nvidia-blackwell-pricing-reshapes-inference-economics) (⚠️ seen via search summary only)
- Realizing the largest B200 cost gains (roughly a 40% cost-per-token cut at 2.5x throughput for 1.5x the price, per one vendor's framing) requires FP4 quantization support and NVLink-72 multi-GPU interconnect — without those, the improvement is smaller — [Digiteria Labs](https://digiterialabs.com/ai/insights/nvidia-blackwell-pricing-reshapes-inference-economics) (⚠️ same caveat as above)
- Reasoning models bill "thinking" tokens (the hidden chain-of-thought the model generates before its visible answer) at the same rate as visible output tokens; OpenAI's o1 lists $15/M input and $60/M output, while o3 lists $40/M input and $160/M output (4x o1's output price) — [TokenMix, "OpenAI o3 Pricing 2026"](https://tokenmix.ai/blog/openai-o3-pricing) (⚠️ seen via search-result summary, not fetched in full)
- Worked example: a coding task on o3 might use 1K input + 5K hidden reasoning + 500 visible-answer tokens = 5,500 tokens billed at the output rate, making the task roughly 4.6x more expensive than the sticker per-token price would suggest — [TokenMix](https://tokenmix.ai/blog/openai-o3-pricing) (same ⚠️ as above)
- Reasoning models are generally described as using roughly 10–100x more compute to generate each reasoning token than a non-reasoning model uses per output token, which is the underlying reason reasoning-token pricing/volume is so much higher — [search-result synthesis citing OpenRouter/CodeAnt reasoning-token explainers](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) (⚠️ synthesized from search snippets, not independently verified against the primary OpenRouter docs page in this session)

### Inferences
- The practical lesson for a training-choice-to-cost mapping: (1) active parameters set a compute floor per token; (2) total parameters set a memory floor that shows up as GPU count needed and as a tax on MoE's compute advantage at high concurrency/batch size; (3) KV-cache size — driven by context length, number of attention heads, and whether the model uses a cache-shrinking attention design (GQA/MLA) — sets how many concurrent users a given GPU pool can serve, which is really a capacity/throughput cost, not just a raw compute cost; (4) hardware generation and quantization (FP8/FP4) multiply cost per token down, but the size of that multiplier is workload- and optimization-dependent, not a fixed constant; (5) "reasoning effort" acts as an output-token multiplier that can dominate all of the above by 2–10x depending on how much hidden reasoning a task triggers.
- Because MoE's compute advantage erodes above a "critical batch size" (~300 tokens on H100, per Epoch AI), a game model should treat MoE's cost saving as being largest at low-to-moderate traffic/utilization and smaller once a model is popular enough to run at large batch sizes — this is a nontrivial, non-obvious mechanic worth surfacing to the player.

### Gaps
- No source in this session gave a clean, primary-source-verified number for how much FP8 vs INT4/FP4 quantization alone (holding hardware and architecture fixed) reduces cost per token; the B200 figures above bundle quantization together with the hardware generation change, so the two effects are not cleanly separated.
- No primary-source number was found in this session for speculative decoding's typical cost/latency reduction (e.g., a specific "%cheaper" or "x faster" figure with a date and source); this remains an unquantified mechanism in these notes.
- No TPU- or Trainium-specific cost-per-token figures were found in this session (searches focused on Nvidia H100/B200 comparisons); TPU/Trainium economics are asserted only qualitatively (as alternative custom silicon) via the a16z LLMflation piece below, not with concrete numbers.
- The DeepSeek V3.1 "active parameters scale toward the full 671B at large batch size" claim (Introl blog) and the several B200-vs-H100 dollar figures above were only seen through WebSearch's auto-generated summaries of those pages, not fetched and read to the end directly — flagged with ⚠️ inline. A report relying heavily on those exact dollar figures should have someone open the primary pages (Introl, SemiAnalysis InferenceX, Digiteria Labs, GMI Cloud, TokenMix) directly.

## Real numbers: serving cost, API price history and collapse, gross margins, compute allocation

### Takeaway
API list prices for frontier-class model output have fallen roughly 60x to 300x from 2023 to 2026 depending on the comparison basis, driven by algorithmic efficiency, hardware generation improvements, and price competition from open-weight models (especially DeepSeek). Despite this, reported/estimated gross margins on inference at OpenAI and Anthropic have been *compressing*, not expanding, in 2025, because inference costs have grown faster than the companies budgeted for even as unit prices fell — implying serving volume and reasoning-token usage are growing faster than per-token costs are dropping.

### Cited Findings
- GPT-4 launched in March 2023 at $30 per million input tokens and $60 per million output tokens — [CloudZero, "GPT-4 API cost 2026"](https://www.cloudzero.com/blog/gpt-4-api-cost/) (⚠️ via search summary; not independently fetched in full)
- GPT-4o launched May 13, 2024 at $2.50/M input and $10.00/M output tokens — [AIFreeAPI, "GPT-4o Pricing Per Million Tokens"](https://www.aifreeapi.com/en/posts/gpt-4o-pricing-per-million-tokens) (⚠️ via search summary)
- By July 2024, GPT-4o mini offered "GPT-4-class" performance at $0.15 per million tokens — [TokenCost, "AI Price Index: LLM Costs Dropped 300x (2023-2026)"](https://tokencost.app/blog/ai-price-index) (⚠️ via search summary)
- As of the search date (referenced within the search results as September 21, 2026), one tracked "frontier token price index" stood at 16, i.e., 84% below its March 2023 base — [TokenCost / TokenMix aggregation, "AI API Pricing History: GPT-4 $60 to GPT-5.4 $15 (50x Drop)"](https://tokenmix.ai/blog/ai-pricing-trends-history) (⚠️ via search summary; index methodology not independently verified — treat the specific "16" and "50x/300x" multipliers as this aggregator's own calculation, not a primary-source figure)
- a16z's "LLMflation" analysis (dated November 2024 per the underlying X/Twitter post cited) found that for a fixed quality level, LLM inference cost has fallen roughly 10x per year for three straight years; a model matching GPT-3-era quality that cost $60 per million tokens in 2021 cost about $0.06 per million tokens by the time of the post — [a16z, "Welcome to LLMflation"](https://a16z.com/llmflation-llm-inference-cost/)
- GPT-4-class output that cost about $30/M input tokens in March 2023 was, as of the a16z piece, available for under $0.50/M tokens from open-weight models like Llama 3.3 70B and DeepSeek V3 — a decline of more than 60x at the frontier-quality level — [a16z, "Welcome to LLMflation"](https://a16z.com/llmflation-llm-inference-cost/)
- a16z attributes the price collapse to three compounding forces: (1) algorithmic efficiency — smaller models matching older larger ones, plus quantization, speculative decoding, and MoE routing; (2) cheaper/faster hardware — Nvidia H100 → H200 → Blackwell, plus custom chips (Trainium, TPUs); (3) price competition from open-weight models — [a16z, "Welcome to LLMflation"](https://a16z.com/llmflation-llm-inference-cost/)
- a16z's caveat: even as per-token price falls, total inference *spend* tends to rise because usage grows faster than price falls — [a16z, "Welcome to LLMflation"](https://a16z.com/llmflation-llm-inference-cost/)
- DeepSeek's own GitHub disclosure (published the weekend before, and reported March 4, 2025): assuming H800 GPU rental at $2/hour, DeepSeek's V3 and R1 models had a combined daily inference cost of $87,072 and daily theoretical revenue of $562,027, i.e., a 545% "theoretical" cost-profit ratio for that 24-hour window (February 28, 2025) — [Computerworld, "DeepSeek claims 545% cost-profit ratio"](https://www.computerworld.com/article/3837452/deepseek-claims-545-cost-profit-ratio-challenging-ai-industry-economics.html); also reported by [Techmeme, citing Bloomberg's Saritha Rai](https://www.techmeme.com/250301/p11) (⚠️ Techmeme page itself returned an HTTP 403 in this session and could not be fetched directly; the Computerworld article, which was fetched and read in full, was used as the primary source for the specific numbers instead)
- DeepSeek explicitly cautioned that its *actual* revenue was "substantially lower" than the theoretical $562,027/day figure because: web and app chat access is free, V3-model queries are cheaper than R1, and developers get discounted rates during off-peak hours — [Computerworld](https://www.computerworld.com/article/3837452/deepseek-claims-545-cost-profit-ratio-challenging-ai-industry-economics.html)
- Analysts quoted in coverage cautioned the 545% figure is "theoretical and difficult to verify" and that cost metrics are "highly subjective to geography, resources, and revenue generation," while still acknowledging DeepSeek had "massively reduced the cost of inference" — [Computerworld](https://www.computerworld.com/article/3837452/deepseek-claims-545-cost-profit-ratio-challenging-ai-industry-economics.html)
- Anthropic projected roughly 40% gross profit margin on selling AI to businesses/developers for 2025 — 10 percentage points below its earlier ~50% estimate — because inference costs (running Claude for paying customers on Google/Amazon servers) came in about 23% higher than budgeted; including free Claude-chatbot-user inference costs, that margin estimate drops to roughly 38% — [reporting synthesized in WebPronews, "Anthropic's Margin Squeeze"](https://www.webpronews.com/anthropics-margin-squeeze-inference-costs-bite-as-revenue-surges/), citing prior reporting from The Information (⚠️ WebPronews itself is a secondary aggregator of The Information's reporting; the underlying The Information article was not directly accessed in this session — treat the specific "40%," "50%," "23%," and "38%" figures as reported-via-secondary-source estimates, not independently verified against the primary paywalled report)
- Anthropic's 2025 revenue is cited at $4.5 billion, with mid-2025 annualized revenue around $3 billion (a ~12x growth rate from prior levels), and 2025 total R&D/marketing/administration spend around $7 billion — [WebPronews](https://www.webpronews.com/anthropics-margin-squeeze-inference-costs-bite-as-revenue-surges/) (same secondary-source caveat as above)
- Earlier (now described as outdated) Anthropic projections had targeted breakeven in 2027, $70B revenue by 2028, and $17B profit by 2028 — [WebPronews](https://www.webpronews.com/anthropics-margin-squeeze-inference-costs-bite-as-revenue-surges/)
- OpenAI projected roughly 46% gross margin for 2025 including inference costs for both paying and non-paying ChatGPT users, but its adjusted gross margin (revenue minus inference cost) reportedly fell to 33% from 40% the year before — below its own 46% target — [search-result synthesis of reporting, cross-referenced against SaaStr's separately reported "70% compute margin in late 2025" figure] — (⚠️ these OpenAI margin figures — 46% target, 33% actual down from 40%, and a separately reported "70% compute margin in late 2025" — come from different secondary aggregations found via WebSearch snippets and were not reconciled against a single primary source in this session; the 33%/40%/46% figures and the "70% compute margin" figure may refer to different metrics or time windows and should not be treated as consistent without further verification. Source pages: [SaaStr, "have ai gross margins really turned the corner"](https://www.saastr.com/have-ai-gross-margins-really-turned-the-corner-the-real-math-behind-openais-70-compute-margin-and-why-b2b-startups-are-still-running-on-a-treadmill), [Forbes, "OpenAI And Anthropic Are Testing Two Very Different AI Business Models" (2026-05-21)](https://www.forbes.com/sites/paulocarvao/2026/05/21/anthropic-openai-enterprise-ai-profitability/))

### Inferences
- The consistent pattern across both OpenAI and Anthropic in 2025 reporting is that *actual* inference cost has repeatedly exceeded projections (Anthropic: 23% over budget on inference; OpenAI: adjusted margin fell year over year despite falling unit prices) — this suggests demand growth and reasoning-token-driven output-volume growth are outrunning the per-token cost declines documented by a16z/Epoch AI, which is the central tension a game should model: falling $/token does not by itself protect margin if usage per user and tokens-per-answer are also rising.
- DeepSeek's 545% figure is best treated as a best-case, off-peak, wholesale-compute-cost snapshot for a single day, not a representative steady-state margin — the company's own caveats (free-tier usage, discounted developer pricing) mean real blended margins are materially lower. For a "CFO" framing in a game, DeepSeek's number is a demonstration that low-level inference *compute* cost can be a small fraction of list price at good utilization, while real-world blended margin is dragged down heavily by free/discounted usage tiers.

## Trade-offs labs face: bigger vs cheaper, reasoning effort, capacity shortages, deprecation

### Takeaway
Labs face a repeated trade-off between a larger/smarter model (higher quality, higher cost/latency) and a smaller/distilled or lower-"reasoning-effort" variant (cheaper, faster, usually good enough for most queries) — this shows up as tiered model families (flagship/balanced/fast) and as user-adjustable "reasoning effort" settings. When demand for a new capability spikes faster than capacity was provisioned, labs impose hard usage caps rather than eat the cost, as OpenAI did within two days of its viral GPT-4o image-generation launch.

### Cited Findings
- OpenAI's GPT-4o-powered image generation feature launched March 25, 2025 and went viral (notably via a "Studio Ghibli-style" image trend); it strained infrastructure so severely that CEO Sam Altman posted that "our GPUs are melting," and OpenAI imposed rate limits within about two days of launch — [Yahoo/Tech, "Sam Altman says ChatGPT's viral image-generation AI is 'melting' OpenAI's GPUs"](https://tech.yahoo.com/articles/sam-altman-says-chatgpt-viral-121804876.html); also reported by [Business Standard](https://www.business-standard.com/technology/tech-news/openai-image-generation-limits-ghibli-trend-sam-altman-125032800179_1.html) and [Gigazine](https://gigazine.net/gsc_news/en/20250328-openai-gpu-are-melting-chatgpt-image-generation/)
- Free ChatGPT users were subsequently limited to three image generations per day as OpenAI managed the capacity shortfall, before the feature was made broadly available to all users by March 31, 2025 — [TechCrunch, "OpenAI's new image generator is now available to all users" (2025-03-31)](https://techcrunch.com/2025/03/31/openais-new-image-generator-is-now-available-to-all-users) (⚠️ via search summary, headline/date only; article body not independently fetched)
- OpenAI's naming system reportedly moved (per one source, described as a more recent change) to a generation-number-plus-durable-tier scheme with three named tiers — "Sol" (flagship/highest intelligence), "Terra" (balanced everyday work), and "Luna" (fastest/lowest cost) — explicitly separating capability tier from model generation — [Toloka AI / search synthesis, "GPT models 2026 explained: From GPT-1 to GPT-5.6"](https://toloka.ai/blog/gpt-models-explained/) (⚠️ via search-result summary only; not independently fetched, and this claim was not cross-checked against an OpenAI primary source in this session — flag to the report writer as needing verification, especially since it materially affects the naming section below)
- Reasoning-token billing (o1 at $15/$60 per M input/output; o3 at $40/$160 per M input/output) is itself evidence of the bigger/smarter-vs-cheaper trade-off being exposed directly to API customers as a dial: more "reasoning effort" == more hidden tokens == higher bill for a given task — [TokenMix, "OpenAI o3 Pricing 2026"](https://tokenmix.ai/blog/openai-o3-pricing) (⚠️ as noted above, via search summary)

### Inferences
- The GPT-4o image-generation episode is a clean, well-documented case study for a game mechanic: a viral feature can create demand that exceeds provisioned capacity within days, forcing a lab to choose between (a) hard rate limits, (b) degrading quality/speed for everyone, or (c) burning margin to keep serving uncapped — OpenAI chose (a).
- The "reasoning effort" dial (visible in o1 vs o3 pricing, and in modern "thinking budget" settings across labs) is functionally the same lever as a distilled-vs-flagship model choice, but applied at request-time rather than at model-选择 time — a game could model both a training-time size choice and a per-query reasoning-effort choice as two separate levers on cost.

### Gaps
- No concrete, dated example was found in this session of a lab explicitly "deprecating an old model to free compute" as a stated capacity-management reason (as opposed to routine lifecycle sunsetting) — the assignment's suggested example was not corroborated with a primary source in this session; this is a gap.
- No comparative cost/quality numbers were found for a specific "distilled" model (e.g., DeepSeek-R1-Distill or GPT-4o-mini as a distillation of GPT-4o) with a serving-cost multiple attached (e.g., "the distilled version costs 1/10th to serve at X% of the quality") — this would need a follow-up search focused specifically on distillation cost/quality trade-off numbers.

## Pricing structures: per-token, subscriptions, enterprise, and how price wars start

### Takeaway
Labs price on two parallel tracks: metered API pricing (input tokens, output tokens — which cost several times more than input because generation is sequential and, for reasoning models, includes billed hidden tokens — and heavily discounted cached-input tokens) and flat-rate consumer subscriptions ($20/month standard tier across OpenAI, Anthropic, and Google, with $100–$200/month "max"/"pro" tiers for heavy users and custom enterprise contracts above that). DeepSeek's December 2024–January 2025 releases (V3, then R1) undercut incumbent API prices by roughly 95%, triggering a broad, ongoing price war.

### Cited Findings
- DeepSeek-V3 API pricing is cited at $0.14/M input tokens and $0.28/M output tokens, with cache-hit input pricing as low as $0.014/M tokens; as of August 2026, DeepSeek V4-Flash is cited as the cheapest listed frontier-adjacent API at the same $0.14/$0.28 per-M rate — [search synthesis, exact aggregator page unclear] (⚠️ this figure came from a WebSearch auto-summary that did not clearly attribute a single source page among several pricing-comparison sites returned; treat as indicative rather than independently verified, and note it may already be stale relative to DeepSeek's actual current pricing page)
- By comparison, OpenAI's GPT-4o was cited at $2.50/M input and $10.00/M output — roughly 18x and 36x DeepSeek-V3's respective rates — [same search synthesis as above] (same ⚠️ caveat)
- Claude Sonnet 5's cached-input price is cited at $0.20/M tokens versus a $2/M standard input rate — a 10x cache discount — [same search synthesis] (⚠️ same caveat; "Claude Sonnet 5" pricing was not cross-checked against Anthropic's own pricing page in this session)
- Google is reported to have responded to DeepSeek's pricing with Gemini 2.0 Flash at $0.10/M input and $0.40/M output — [same search synthesis] (⚠️ same caveat)
- One aggregator's framing: "Anthropic cut Claude prices 67%, models that cost $60/M tokens now cost $1–2, and DeepSeek forced a global price war," with the overall 2025–2026 price war described as collapsing costs "90–97% for equivalent intelligence" — [BizScoreAI, "DeepSeek Triggered an AI Price War"](https://bizscoreai.com/blog/deepseek-ai-price-war/) (⚠️ via search summary; specific "67%" and "90–97%" figures not independently verified against a primary Anthropic pricing announcement)
- DeepSeek-V3 was released December 2024 and DeepSeek-R1 in January 2025, both matching GPT-4o/Claude on key benchmarks while priced roughly 95% below incumbent API rates — [search synthesis of multiple pricing-comparison pages, e.g., IntuitionLabs and Spheron Blog pricing comparisons](https://intuitionlabs.ai/articles/llm-api-pricing-comparison-2025) (⚠️ via search summary)
- Consumer subscription tiers cluster tightly around $20/month: ChatGPT Plus $20, Claude Pro $20 ($17/month if paid annually), Google AI Pro $19.99 — [Morphllm, "ChatGPT vs Claude vs Gemini (June 2026)"](https://www.morphllm.com/comparisons/chatgpt-vs-claude-vs-gemini) (⚠️ via search summary)
- Above the standard tier: Claude offers Free, Pro ($20), and two "Max" tiers at $100/month (5x usage) and $200/month (20x usage); ChatGPT offers Free, Plus ($20), and Pro ($200/month, unlimited access to advanced reasoning models) — [search synthesis of the same comparison pages] (⚠️ via search summary)
- Team plans: ChatGPT Team is cited at $25/user/month (annual) or $30/user/month (monthly); Claude Team is cited at a similar $25–30/user/month; Enterprise plans (Claude Enterprise, ChatGPT Enterprise, Gemini for Workspace) are cited in the $30–60+/user/month range with custom, sales-negotiated pricing above that based on security requirements, usage volume, and integrations — [search synthesis of the same comparison pages] (⚠️ via search summary)

### Inferences
- The consistent input-vs-output-vs-cached-input price ratio pattern (output priced ~4x input; cached input priced ~10x cheaper than fresh input) reflects the underlying serving mechanics: output generation is sequential/latency-bound (one token at a time, can't be parallelized within a single response) while input processing (prefill) can be batched and cached-input tokens reuse the KV cache instead of recomputing it — this is a good mechanic for a game's pricing screen (three separate price knobs: input, cached-input, output).
- The tight ~$20/month clustering of standard subscription tiers across three competing labs (OpenAI, Anthropic, Google), each cutting prices or matching a rival soon after a competitor move (DeepSeek → Gemini Flash repricing; DeepSeek → Anthropic price cut cited above), suggests subscription and API pricing both behave as a fairly fast competitive-matching game, not independent per-lab decisions — useful if the game wants a "rival labs react to your pricing" mechanic.

## Model naming: how labs name, version, and signal size tiers

### Takeaway
Every major lab uses a three-part naming pattern — family name, version number, and a size/flavor qualifier — but each lab encodes "smart vs. fast/cheap" differently: Anthropic uses poetic tier names (Haiku/Sonnet/Opus) attached to a shared version number; Google uses a tier word appended to a version number (Gemini 1.5 Flash/Pro/Ultra); OpenAI's scheme has shifted multiple times, most confusingly mixing a "GPT-N" numbered line with a separately-numbered "o-series" reasoning line (o1, o3), which independent commentary calls out as a genuine naming failure that made it hard for users to know which model they were using.

### Cited Findings
- General pattern observed across labs: "AI model names are usually three parts: the family, a version number, and a size or flavor word" — [Chatday HUB, "What All Those AI Model Names Actually Mean"](https://www.hub.chatday.ai/blog/ai-model-names-explained) (⚠️ via search summary)
- OpenAI's naming evolved from simple sequential numbering (GPT-1, GPT-2, GPT-3) to a more complex, overlapping scheme (GPT-4o, o1, o3-mini-high) — [Toloka AI](https://toloka.ai/blog/gpt-models-explained/) (⚠️ via search summary)
- The "o" in GPT-4o stands for "omni," signaling multimodal (text/audio/image) capability rather than a reasoning tier — [search synthesis](https://www.openpr.com/news/4036541/chatgpt-s-confusing-model-names-explained-the-difference) (⚠️ via search summary)
- OpenAI's o-series (o1, o3, o3-mini, o4-mini) is a separately-numbered line built for extended reasoning, released alongside (not instead of) the GPT-N line — e.g., "OpenAI releases GPT-4.1, o3 and o4-mini" as a single announcement — [Pat McGuinness / Substack, "OpenAI releases GPT-4.1, o3 and o4-mini"](https://patmcguinness.substack.com/p/openai-releases-gpt-41-o3-and-o4) (⚠️ via search summary)
- One source describes a more recent OpenAI shift to generation-number-plus-tier naming with tiers "Sol" (flagship), "Terra" (balanced), and "Luna" (fast/cheap) — [Toloka AI](https://toloka.ai/blog/gpt-models-explained/) (⚠️ flagged above as unverified against a primary OpenAI source; note this is also consistent with references to "gpt-5.6-sol" and "gpt-5.6-terra" as real, currently-used model identifiers elsewhere in this environment's own configuration, which lends it some corroboration, but this was not independently confirmed via an OpenAI announcement in this research session)
- Google's assistant/model naming moved from "Bard" to "Gemini," with size/speed tiers appended directly to a version number, e.g., "Gemini 1.5 Flash" — described by one commentator as sounding "like a camera feature" — [Chatday HUB](https://www.hub.chatday.ai/blog/ai-model-names-explained) (⚠️ via search summary)
- Anthropic names its assistant "Claude" and its model-size tiers with poetic words — Haiku (smallest/fastest), Sonnet (mid-tier), Opus (largest/most capable) — attached to a version number (e.g., "3.7 Sonnet"); one critique specifically calls this "poetic names, but become confusing when versions... get added" — [Chatday HUB](https://www.hub.chatday.ai/blog/ai-model-names-explained) (⚠️ via search summary)
- The core naming-confusion critique found across sources: labs blur the line between "the assistant product" and "the underlying model," e.g., Google's "Gemini" names both the app and the model family, and OpenAI's ChatGPT app can run on GPT-4o, o1, or o3-mini depending on user selection — making it hard for an ordinary user to know which model they are actually talking to — [Solveo Co / Medium, "AI naming is a mess. Can someone fix It?"](https://solveoco.medium.com/ai-naming-is-a-mess-can-someone-fix-it-e002f6a3679f) (⚠️ via search summary, article not independently fetched in full)

### Inferences
- Across labs, the size/tier qualifier is the consistent signal a player would recognize: a "small" word (Haiku, Flash, Nano, mini, Luna) reliably means cheaper/faster/smaller, a "mid" word (Sonnet, Pro, standard/no-suffix) means balanced, and a "large" word (Opus, Ultra, Ultra/flagship, Sol) means most capable and most expensive — this three-tier mental model (small/mid/large, independent of the numeric version) is a reusable naming convention for a game's model-naming feature.
- Numeric version increments (Gemini 1.5 → 2.0, Claude 3 → 3.7, GPT-4 → 4.5/5) appear to signal "same tier structure, smarter/newer generation," while a completely new family name (e.g., "o" line, or a "Sol/Terra/Luna" scheme replacing "GPT-N") appears to signal a genuine architecture or product-strategy break — useful for a game feature where the player chooses whether a new model is a numbered increment (safe, iterative) or a rebrand (bigger risk/reward, resets user familiarity).

### Gaps
- Llama's own naming convention (Llama 2, Llama 3, Llama 3.1 8B/70B/405B, size-in-parameter-count naming) was listed in the assignment's key questions but not specifically searched in this session — this is a gap; Llama uses raw parameter-count-in-the-name (e.g., "70B") as its size signal, distinct from the poetic/adjective approach of the other labs, which would be worth adding to a naming-conventions list, but this note itself is drawn from general background knowledge, not a source verified in this session, so it should not be cited as a research finding without a follow-up check.
- DeepSeek's own naming convention (V3, R1 — where "V" appears to denote a general-purpose version line and "R" a reasoning-focused line, paralleling OpenAI's GPT-N/o-N split) was not specifically corroborated with a primary DeepSeek source in this session.
- The claim about OpenAI's "Sol/Terra/Luna" tier renaming could not be verified against a primary OpenAI announcement in the time available; given how much a naming feature might lean on this, it is flagged as the single most important open verification item from this research pass.

## Transfer notes: a simple serving-cost model for a 20-minute AI-lab game

This section proposes a deliberately simple, game-appropriate cost model built from the mechanisms and numbers above. It trades precision for legibility — every knob should visibly move the numbers a player sees, and the CFO's comments should follow directly from the same formula so the game feels internally consistent.

**Suggested formula — cost to serve one user for one month:**

`monthly_cost_per_user = tokens_per_user_per_month × cost_per_token`

Break `cost_per_token` into a base rate modified by five training-choice multipliers and one hardware-era divisor, mirroring the real mechanisms found above:

`cost_per_token = base_rate × active_size_mult × architecture_mult × context_mult × reasoning_mult / hardware_era_mult / quantization_mult`

- **active_size_mult** (from "active parameters per token," Epoch AI section above): scale roughly linearly with the model's active-parameter tier the player picked at training time (e.g., small=1x, medium=4x, large=16x, matching real active-parameter ratios between model tiers like Haiku/Sonnet/Opus or Flash/Pro/Ultra).
- **architecture_mult**: Dense = 1x (full active_size cost); MoE = a discount factor (e.g., 0.3–0.5x of an equivalent-total-size dense model) that the player unlocks by choosing MoE at training time — but pair it with a capacity mechanic (below) that erodes the discount at high user counts, mirroring the real "critical batch size" effect where MoE's edge shrinks under heavy load.
- **context_mult**: scale with chosen max context length (e.g., 1x for short/8K context, 2x for 128K, 4x for 1M+), representing KV-cache growth; give the player a GQA/MLA-style "efficient attention" training choice that halves this multiplier, mirroring the real "60% cheaper" MoE/GQA long-context finding above.
- **reasoning_mult**: a player-set "reasoning effort" dial (off/low/medium/high) that multiplies output tokens per answer by roughly 1x/2x/5x/10x, mirroring the real o1-vs-o3 hidden-reasoning-token cost blowup (up to ~4.6x on a single task in the cited example, with sources describing reasoning tokens costing 10-100x more compute per token to generate).
- **hardware_era_mult** (divisor, so bigger = cheaper): 1x for an "H100-era" starting hardware choice, rising to roughly 6–7x cheaper for a "B200/Blackwell-era" hardware upgrade the player can invest in, matching the ~6x-throughput/~7x-cost-per-token figures cited above (acknowledging in-game that this is the *upper end* of real reported improvements, not guaranteed).
- **quantization_mult** (divisor): 1x for full/FP16 precision, ~1.5–2x cheaper for FP8, and a further step for FP4/INT4 that the game can gate behind the B200-era hardware choice (mirroring the real finding that the largest Blackwell gains specifically require FP4 support).

**Revenue and margin:**

`monthly_revenue = user_count × price_per_user_per_month` (or, for API-priced play, `tokens_sold × price_per_token`, split into input/output/cached-input at roughly a 1:4:0.1 ratio per the real Claude/GPT pricing ratios found above)

`gross_margin = (monthly_revenue − user_count × monthly_cost_per_user) / monthly_revenue`

Calibrate the game's "healthy" range using the real 2025 figures above: Anthropic ~38–40% and OpenAI ~33–46% (range reflects the unresolved figures noted in the Gaps above) — a game should treat anything below roughly 30% as "CFO alarm" territory and above ~50% as unusually good, consistent with both companies undershooting their own margin targets in 2025.

**Capacity cap (compute-shortage mechanic):**

Give the game world a fixed GPU pool (in "H100-equivalent units," scaled by the hardware_era_mult above). If `user_count × tokens_per_user_per_month` implies more compute-seconds than the pool provides, trigger the real-world response seen in the GPT-4o image-generation launch: the game forces a choice between (a) hard usage caps / waitlist (protects margin, angers users, mirrors OpenAI's actual 2025-03-25→03-27 response), (b) degrade quality/speed for everyone (e.g., auto-drop to a cheaper distilled model under load), or (c) burn margin by renting emergency short-term compute at a price premium (mirrors on-demand cloud GPU pricing being markedly higher than reserved capacity).

**What the CFO would say (sample lines, each tied to a real mechanism above):**
- If reasoning_mult is set high and price wasn't raised: *"Our hidden reasoning tokens are eating margin — this is what happened to o3 pricing versus o1; input price barely moved but output cost quadrupled."*
- If architecture_mult = MoE but user_count just crossed the capacity threshold: *"Our MoE discount is vanishing at this traffic level — we're now loading almost the whole model per batch, just like DeepSeek's V3.1 at scale."*
- If a hardware_era upgrade is skipped while a rival is implied to have upgraded: *"We're serving on last-generation silicon. Every rival on Blackwell is paying a fraction of our cost per token."*
- If free-tier user count is large relative to paying users: *"Our blended margin looks fine on paper, but free-tier serving is the same trap Anthropic and DeepSeek both flagged — it drags real margin well below the headline number."*
- If gross margin < 30%: *"We are below both OpenAI's and Anthropic's reported 2025 margins. Cut reasoning effort, raise price, or cap free usage."*

**Naming conventions and prompts for player-named models (for a naming feature):**
- Give the player three tier-name slots (small/mid/large or fast/balanced/flagship) and let them pick a naming *style* at the start of the game, each modeled on a real lab: (1) *Poetic/Anthropic-style* — pick three words on a theme (their example: musical forms Haiku/Sonnet/Opus) for small/mid/large; (2) *Descriptive/Google-style* — a shared version number plus a literal speed/scale word (their example: Flash/Pro/Ultra); (3) *Numeric/Llama-style* — literally name the tier after its size (e.g., "8B," "70B," "405B"); (4) *Fractured/OpenAI-style* — let the player accidentally create two parallel numbered lines (a "main" line and a "reasoning" line) and have the game needle them with the real naming-confusion critique ("can your users tell 4o from o4?") if they do.
- Fun in-game naming prompts: "Your flagship model needs a name that sounds expensive and smart — bidders in the boardroom loved 'Opus' and 'Ultra.'" / "Your cheap-and-fast model needs a name that sounds instant — think 'Flash,' 'Haiku,' 'Nano,' 'Luna.'" / "Picking a totally new family name instead of bumping the version number is a bet that pays off only if the new model is a real leap — are you sure this isn't just GPT-4.5 again?" (referencing the real critique that a name change should track an actual capability break, not just a marketing refresh).
