# Warnings precede cards; cards precede consequences

Across every management, strategy, and narrative-choice game surveyed — Frostpunk, RimWorld, Stellaris, Factorio, Crusader Kings III (CK3), Game Dev Tycoon (GDT), Plague Inc., Democracy 4, Suzerain, Reigns, and FTL — the strongest convergent pattern is a **two-tier delivery pipeline**: a cheap, persistent, low-commitment signal (an icon, a feed headline, an advisor line) precedes a costly, resolvable decision (a modal card or pop-up with 2–4 branching choices), and the two tiers use different visual grammars so the player can tell at a glance which kind of information they're looking at. A second, equally strong pattern is that **almost no surveyed game shows the player a raw number when a hidden or soft stat is at stake** — instead they use color-coded envelopes (RimWorld), named severity stages (Stellaris' "Severe Deficit" vs. "Catastrophic Deficit"), hedged magnitude words ("Hope will increase slightly," Frostpunk), or the changing composition of a news feed (Plague Inc.'s ticker) to communicate direction and intensity without a figure. A third pattern, load-bearing for "what happens if the player ignores it," splits into two families: a **hard, binary deadline** (Frostpunk's ultimatum, CK3's four-month auto-select-the-first-option rule) versus a **graduated ladder** where every stage already costs something and escalation is continuous rather than a countdown (Stellaris' Situations, Prison Architect's riot ladder). Separately, a companion note on Game Night: AI Lab's own repository confirms the game's sim (`sim/events.js`, `sim/turn.js`, and the two event-data catalogs) already implements a warning-then-card pipeline, a two-card-per-turn cap with overflow deferral, and a "passive fallback" auto-resolution rule for ignored cards — meaning most of the mechanical decisions this report might otherwise recommend are already built and tested; what remains open is purely the visual and interaction design of the screens that will surface that data, which has not yet had a design pass or an owner-reviewed mockup. Several of the sourcing gaps below are structural (a run of HTTP 402/403 errors against Fandom-hosted wikis) rather than a failure to look, and every claim resting on a partial or blocked source carries its original ⚠️ flag through to this synthesis, per the provenance rule governing this report.

## Card anatomy varies by genre, but four shapes recur

The physical layout of a dilemma card clusters into four recognizable shapes across the ten games and one modding API surveyed. The **minimalist swipe card** (Reigns) puts one character portrait and one line of dialogue on screen, offers exactly two choices via left/right swipe, and shows no numeric costs anywhere in the base interface — reputation is tracked only as four unlabeled bars ([MMOCulture summary of Reigns mechanics](https://mmoculture.com/2026/07/reigns-beyond-pre-registration-news/) ⚠️ WebSearch synthesis, not a single primary source read in full). The specific claim that hovering toward a side previews *which* bar will move without showing *how much* — the exact mechanic Game Night's own key questions asked about — could not be confirmed from a primary source in this research pass; the Game Developer interview with designer François Alliot was fetched and read in full but discussed creative philosophy, not UI implementation, and the dedicated GDC talk on the swipe system exists only as a paywalled listing ([GDC Vault: "The Casual (but Regal) Swipe"](https://www.gdcvault.com/play/1024278/The-Casual-(but-Regal)-Swipe), title only) — so this widely-repeated player description should be treated as **unverified from primary sourcing** (⚠️).

The **text-box event with a vertical choice list** (FTL) drops the portrait entirely: an italicized narrative paragraph is followed by unstyled choice lines, with "blue options" specially colored to mark choices gated behind equipment or crew the player happens to have ([FTL Wiki: Blue Options](https://ftl.fandom.com/wiki/Blue_Options) ⚠️ WebSearch synthesis only — direct fetch returned HTTP 402 on two attempts). FTL never previews numeric outcomes in the base game at all; the existence of a player-made mod that tags roughly 1,000 lines of event text with their consequences is itself evidence of how completely the base game withholds that information ([GitHub: thrnz/FTLEventTags1.6](https://github.com/thrnz/FTLEventTags1.6) ⚠️ seen only via search snippet). The **portrait-window pop-up with a queue** (CK3) is the richest format documented with primary sourcing: the event window supports up to five character-portrait slots (`left_portrait`, `right_portrait`, and three lower positions), any number of dialog options including zero for pure-notification events, and flavor-text tooltips on each option — all confirmed by reading CK3's own modding wiki in full ([CK3 Wiki: Event modding](https://ck3.paradoxwikis.com/Event_modding)). Whether CK3's option tooltips also preview the *numeric or directional effect* of a choice (not just flavor text) — the detail Game Night's brief most wanted from CK3 — was not confirmed in the retrieved text of that page, so it remains a plausible-but-unverified claim (⚠️), and the mechanics of CK3's on-screen notification queue/outliner (how many events can stack, whether they visually pile as cards) rest on WebSearch synthesis of the Interface page and a forum thread, not a page fetched and read directly (⚠️).

Game Dev Tycoon collapses all of its event varieties — random events, industry news, contract offers, staff requests, the annual G3 trade-show pop-up — into **one underlying `Notification` object**, confirmed directly from Greenheart Games' own modding API documentation: it carries a title, a body (which can paginate across multiple screens via a `{n}` token), a 200×200px image, 2–3 `options` buttons, and a `type` field (`Default`, `PlatformNews`, `IndustryNews`, `Events`, `AutoPopup`) that determines whether the notification forces itself onto the screen or waits in a sidebar according to the player's own "Messages" settings ([Notification, greenheartgames/gdt-modAPI Wiki](https://github.com/greenheartgames/gdt-modAPI/wiki/Notification)). Every named GDT random event this research could enumerate — a security-upgrade staff request, a Nigerian-scam phishing offer, a patent-infringement claim, an air-conditioner complaint that escalates from a smaller to a larger fee if declined — reduces to a binary or ternary pay/decline/third-option shape (⚠️ the underlying wiki page listing these events was reachable only through a read-through proxy after a direct 402 error), which is the same 2–3-choice shape Game Night is already built around. What GDT's sources could **not** establish, despite a dedicated search, is whether the game's time simulation pauses while a notification dialog is open — the strongest signal found was one community mod's README implying dialogs already have *some* baseline pause behavior for the mod to override, which is a weak inference, not a stated fact (⚠️). Game Dev Story's actual on-screen presentation is even thinner: Kairosoft's own wiki documents *what* triggers (an annual "Gamedex" convention, a "Global Game Awards" ceremony gated by a review-score threshold, a recurring vendor) and their numeric effects, but explicitly does not describe whether these appear as a popup, a text box, or a visiting character sprite — the dedicated Magazine Reviews page is a stub containing only a score table (⚠️ Game Dev Story's presentation layer is thinly sourced across every source reached in this pass, and this gap is the source material's own limitation, not a partial read on the researcher's part).

## Hiding the number without hiding the stakes

Every game in this research that keeps a stat hidden or soft still finds a way to communicate direction and magnitude without a figure, and the techniques cluster into four reusable patterns. The first is **color or icon severity coding without a number attached**: RimWorld's event "Letters" are envelope icons colored blue (good), grey (neutral), yellow (bad), or red (direct threat), with persistent, non-dismissible "Alerts" (as opposed to one-shot Letters) staying visible for as long as their underlying condition — a starving colonist, say — remains true ([RimWorld Wiki: Events](https://rimworldwiki.com/wiki/Events), read in full). The second is a **named severity ladder**: Stellaris represents a slow-building problem as a single persistent "Situation" object with a 0–100 progress bar that the player never sees as a raw number, instead reading the ladder through discrete stage names — a shortage might progress from "Minor Deficit" through "Major," "Severe," and "Catastrophic Deficit" — each stage both narrating urgency and imposing a new, felt mechanical penalty ([Stellaris Wiki: Situations](https://stellaris.paradoxwikis.com/Situations), read in full). The third is **hedged magnitude language attached to a named meter**: Frostpunk's Book of Laws reports consequences as "Hope will increase slightly" or "Discontent will rise moderately" rather than as deltas, and deliberately keeps exact law costs opaque until after a law is actually passed (Gabriel Chauri, ["Frostpunk – Player's Decisions in the Book of Laws"](https://www.gabrielchauri.com/frostpunk-decisions/), read in full). The fourth, and the most purely diegetic, is **letting the composition of a feed do the talking**: Plague Inc.'s in-game news ticker mixes cosmetic jokes with plague-relevant headlines early on, and as a plague progresses the relevant headlines crowd out the noise "to the point of them becoming the only news displayed" late-game — meaning the signal-to-noise ratio of the feed itself, not any single headline, is the urgency cue ([Plague Inc. Wiki: News](https://plagueinc.wiki.gg/wiki/News), read in full). Democracy 4 goes a step further and decouples flavor entirely from mechanics: its "media report" system generates plain-text, journalistic-style stories about named (procedurally generated) citizens suffering a consequence, and these reports are deliberately given **zero mechanical effect** on the simulation — their only job is emotional feedback, kept structurally separate from the game's actual mechanical "Situations" system (Cliff Harris, [Positech Games blog: "Consequences in Democracy 4"](https://www.positech.co.uk/cliffsblog/2020/04/11/consequences-in-democracy-4/), read in full). Suzerain follows a related but distinct approach: it shows some numeric stats openly (Economic Development, Government Budget) while explicitly keeping others hidden (Alignment, Unrest, Opinion) and reporting the hidden ones only through narrative reflection — an advisor's reaction, a news brief, a later event becoming available or unavailable — never a bar tied to that specific hidden stat (⚠️ this claim rests on a Steam Community/aggregated design summary via WebSearch synthesis, not a single primary source read in full; the exact layout of a Suzerain "decision prompt" screen — portraits, body length, choice count, whether it is timed — could not be retrieved from any source reached in this pass, since the two most promising pages, a dedicated "Decision Prompts" catalogue and guide, both returned HTTP 403).

## Ignoring a warning triggers a default, not a void

What happens when a player does nothing splits cleanly into two mechanical families, both well-documented. The **hard-deadline family** resolves on a clock: CK3's own wiki states plainly that "if the player has not chosen an option after four months on the same date, the first choice gets autoselected" ([CK3 Wiki: Events](https://ck3.paradoxwikis.com/Events), read in full) — the cleanest "ignore it and a default happens" rule found in this research, notable for defaulting specifically to whichever option is listed *first* in the event's own script. Frostpunk's ultimatum mechanic works similarly but with harsher stakes: crossing a critical threshold on Hope or Discontent triggers a countdown of roughly two to three days (sources disagree on the exact figure) during which the player must move the stat back by an approximate margin or the settlement ends outright (⚠️ this entire mechanic rests on secondary sources — gamepressure.com and several Steam Community threads — because both of Frostpunk's own wiki pages on Events and the Book of Laws returned HTTP 402 on every fetch attempt in two separate research passes; the "2 days" vs. "2–3 days" and "15%" figures conflict slightly between sources and should be treated as approximate). The **graduated-ladder family** instead makes every stage of delay cost something in its own right, with no single moment of failure: Stellaris' staged Situations impose a live mechanical penalty (reduced output, lower stability) at every named stage, so ignoring a warning is not a bet against a future event but an already-accruing cost, and the player can pick different "approaches" mid-ladder to change the Situation's progress rate rather than only watching a countdown ([CK3/Stellaris Wiki: Situations](https://stellaris.paradoxwikis.com/Situations), read in full). Prison Architect's riot mechanic follows the same shape through many small steps rather than one hard threshold: individual prisoner unhappiness escalates through "irritated" and "angry" states, then property destruction and attacks on staff, and ten or more prisoners rioting simultaneously triggers prison-wide "riot status," with an uncontrolled long-lasting riot as an explicit failure condition in Sandbox mode — confirmed by reading the official wiki's Riots page in full, which notably does **not** describe any dedicated pre-riot warning UI in the original game; that layer (a "Frustration Bar" plus "Admin staff" who "pop up and warn" the player) appears to be new to the sequel, and could only be sourced to a WebSearch synthesis of Paradox's own feature-highlight page, not a fetch of the page itself (⚠️) ([Prison Architect Wiki: Riots](https://prisonarchitect.paradoxwikis.com/Riots), read in full).

Queueing multiple pending decisions is handled by giving warnings and cards different notification channels rather than by stacking cards on top of each other. Factorio draws the cleanest line: **Alerts** (something just happened — an entity destroyed, a train out of fuel) are typed by icon, optionally play a sound, and expire automatically after 5 to 30 seconds regardless of whether the underlying problem is fixed, while a separate, visually distinct **warning icon** painted directly on the affected building persists for as long as the condition is actually still true; players can individually mute or configure roughly sixteen alert types from a dedicated panel, handing alert-fatigue control directly to them ([Factorio Wiki: Alerts](https://wiki.factorio.com/Alerts), read in full). RimWorld's Letter/Alert split mirrors this almost exactly under different names — one-shot, dismissible, color-coded Letters versus persistent, non-dismissible Alerts tied to a live condition and viewable as a running list via a hotkey (same source as above). CK3 handles true queueing (several events pending at once) through an on-screen outliner and a notification feed in the corner, with hotkeys to open and resolve items from that queue, though the precise stacking behavior — how many can be pending simultaneously, whether they visually pile as cards — rests on WebSearch synthesis of the Interface page and a Paradox forum thread rather than a directly fetched primary source (⚠️). GDT's `Notification` object supports the same idea structurally: its `type` field routes lower-priority notifications into a sidebar/message list governed by a player-adjustable "Messages" setting, while a small number of `AutoPopup`-typed notifications always force themselves onto the screen regardless of that setting — meaning GDT gives players a way to demote noisy notification types out of the interrupting path, an explicit, tunable knob rather than a fixed behavior ([Notification, greenheartgames/gdt-modAPI Wiki](https://github.com/greenheartgames/gdt-modAPI/wiki/Notification)). General UX writing on "alert fatigue" converges on the same handful of remedies these shipped systems already embody — prioritize by actionability, separate transient from persistent, let players mute by type, use restrained sensory design and reserve strong interruption for genuinely actionable items — though this general literature was reached only through WebSearch synthesis after a direct fetch of the most promising article returned HTTP 403, so it is weaker-sourced than the game-specific, fully-read findings above (⚠️) ([UX Collective: "How to design to alert users without overwhelming them"](https://uxdesign.cc/how-to-design-to-alert-users-without-overwhelming-them-4bb41feda9f0)).

## Advisors and feeds foreshadow before a card ever appears

The pre-card warning layer, across every game that has one, is delivered by one of two personas: a **standing readout the player must proactively check** (a dashboard, an almanac tab), or a **pushed, in-character line that interrupts or narrates**. Tropico 5's Almanac exemplifies the first: dedicated tabs for Politics, a rebel/threat level, Foreign Relations, and a seven-category Happiness breakdown let a player see which faction is about to turn hostile before a revolt happens, entirely on their own initiative ([gamepressure.com: Tropico 5 Almanac guide](https://www.gamepressure.com/tropico5/6-almanac/zf642c), read in full). Two Point Hospital's PA/Tannoy system exemplifies the second: a deadpan, voice-acted announcer delivers warning-style lines while a problem is already live in the hospital — a diegetic audio layer riding on top of the simulation rather than a UI panel (⚠️ sourced only to Steam Community discussion snippets and a TV Tropes page; the dedicated wiki page for this system returned HTTP 402 and could not be verified for exact wording). Civilization VI's on-screen Advisor, by contrast, appears from the sources reachable in this pass to be organized mainly around build/tech recommendations rather than pre-crisis threat warnings, though this could not be confirmed from a full read — both relevant Civilization wiki pages returned HTTP 402, so the claim that Civ6 advisors do or do not issue proactive warnings of impending war or unhappiness remains an open gap (⚠️).

News feeds and tickers are the clearest verified model for a foreshadowing channel that escalates on its own, separate from any single advisor. Plague Inc.'s news screen mixes cosmetic jokes ("Tower of Pisa leaning the wrong way") with headlines that specifically preview an upcoming rule change the player will have to play around, in a documented rough sequence: early detection ("Scientists concerned over [plague name]") gives way to escalating countermeasures ("[Country] starts cure research"), then to targeted counters aimed at the player's own strategy, then to endgame headlines — meaning the ticker doesn't just add flavor, it gives an attentive player a real window to adapt before the mechanical effect actually lands ([Plague Inc. Wiki: News](https://plagueinc.wiki.gg/wiki/News), read in full). Cities: Skylines' Chirper is offered by the available sources as a cautionary counter-example rather than a model to copy: secondary sources describe it as occasionally reflecting citizen moods but frame it primarily as cosmetic, comedic, and fully toggleable — a feed that never ties into consequences appears to train players to treat it as decorative noise rather than as a signal worth reading (⚠️ both claims rest on WebSearch synthesis; the dedicated wiki page returned HTTP 402 and Paradox's equivalent page could not be located at all). Oxygen Not Included's "Red Alert" mode — a full-screen red edge glow plus red-highlighted notifications, triggered manually and forcing colonists to prioritize work over their own needs — offers a fifth severity-communication channel (a whole-screen ambient wash) beyond the four already catalogued above, though this too rests on search snippets rather than a fetched wiki page (⚠️).

## What Game Night's own specs, plans, and sim already lock in

A companion research note read the Game Night: AI Lab repository directly — the design spec, three implementation plans, the design skill's taste/learnings logs, two approved mockups, and every relevant sim source file in full — and found that the mechanical side of this exact design question is **already decided and shipped in code**, while the visual/interaction design is the one piece still open. The spec's §6c states the rule in plain language: incidents caused by the player's own choices "first appear as a small sign (a feed post, an advisor aside)... Ignoring it turns it into a full event card the next turn, with 2–3 costly choices," explicitly rejecting both "plain cards only" (no chance to catch trouble early) and "multi-turn story chains" (too much writing for a jam-scoped project) — this is stated as an owner pick, not an open question (`docs/superpowers/specs/2026-09-25-game-night-ai-lab-design.md` §6c). The sim (`sim/events.js`, `sim/data/events.js`, `sim/data/events6c.js`, `sim/turn.js`) implements this exactly: a hard cap of two pending cards per turn (`MAX_CARDS = 2`), with a third triggering event pushed back into a "deferred" warning state that has no feed post and cannot be addressed until a slot frees up (one row, `pooling`, is explicitly exempted from this cap); a warning that is never acted on and matures into a card that goes unanswered by end of turn is auto-resolved via a documented "passive fallback" rule — the row's own `fallback` field if set, otherwise its last listed choice — and this auto-resolution emits its own event for an end-of-turn toast. Every one of the 36 static event rows across both data files was read and checked: choice counts are 2 or 3 in every existing row (the data contract technically allows up to 4), and no `cost` string anywhere shows a hidden variable as a number — costs are either a literal, always-visible dollar figure or a qualitative phrase like "staff trust" or "public trust," matching the project's own hard "no hidden numbers in player text" rule verbatim.

What the same note found **not yet decided** is the presentation layer these mechanics will sit inside. The advisor "!"/"!!" markers already exist in the office UI and are driven by hidden briefing bands (`calm`/`uneasy`/`alarmed`), but they currently have no click handler, no "read" state, and no connection to `pendingEvents` or `warnings` at all — the task of making them clickable, and clarifying whether they double as an events indicator or need a second marker, is unresolved. No file in `state.warnings` carries its own display text; the practical text source is the feed entry already pushed when the warning fired, and nothing in the plans specifies this explicitly. Most importantly for a design pass: no mockup, and no dated entry in the design skill's `LEARNINGS.md`, exists yet for the event-card dialog, the warning-toast styling, or the backers/opposers chip treatment — every other comparable screen in the project (compute, recipe, the era-card banner) has a recorded owner reaction to a shown mockup; this one does not, meaning the design skill's own gates (a mockup spread with a genuinely experimental option, screenshot critique, a LEARNINGS.md update) still need to run before implementation, not be skipped in favor of a single "faithful K2 extension."

## Implications for Game Night

The research above maps onto Game Night's stated constraints — warning-then-card delivery, 2–3 costly choices, up to three pending cards when pooling fires, unanswered cards auto-resolving via `fallbackChoice`, no hidden numbers in player text, and an owner preference for diegetic in-office presentation (the approved feed phone and the Lumen robot) — as a set of patterns and trade-offs, not a single prescribed layout.

- **Which persona speaks, and where, is a real design fork with precedent on both sides.** GDT collapses everything into one generic `Notification` popup regardless of source; CK3 uses up to five portrait slots to stage a scene diegetically inside the same window; Two Point Hospital and Prison Architect 2 push warnings through a voiced or named character (PA announcer, Admin staff) layered on top of the live simulation rather than a UI panel. Game Night already has both a feed phone (text-based, Plague-Inc.-ticker-shaped) and a Lumen robot (character-based, closer to the PA/Admin-staff pattern) approved as separate channels — the open question the research surfaces is whether warnings, cards, or both should route through each, and whether giving both channels the same information is redundant noise (per the alert-fatigue literature, ⚠️ secondary-sourced) or useful reinforcement (per Factorio's deliberate icon-plus-sound-plus-mute-panel redundancy, fully sourced).
- **The choice between a hard deadline and a graduated ladder changes what "ignoring a warning" feels like.** Frostpunk's ultimatum (⚠️ figures unverified from a primary source) makes ignoring a warning a bet against a countdown with a binary outcome; Stellaris' staged Situations and Prison Architect's riot ladder make every turn of delay already cost something, with no single failure moment. Game Night's own `fallbackChoice` mechanic — an unanswered card resolves automatically, at the cost of whatever its default choice costs — sits structurally closer to the graduated-ladder family (the "failure" is just the fallback choice happening, not a game-over check), which suggests the warning-toast and card framing could lean on "this is already costing you something" language rather than countdown-clock urgency, though either framing is defensible and this report does not choose between them.
- **Hiding numbers while keeping stakes legible has four independently-precedented techniques, and they compose.** Named severity words (Stellaris' stage labels), color/icon coding without a number (RimWorld's envelope colors), hedged magnitude phrasing tied to a named meter (Frostpunk's "slightly"/"moderately"), and feed-composition drift (Plague Inc.'s noise-to-signal ratio) are all real, shipped answers to the same "no numbers" constraint Game Night already enforces in its card-cost strings. The advisor "!"/"!!" markers, the feed phone, and the Lumen robot each map onto a different one of these techniques (character marker ≈ Two Point Hospital/Prison Architect 2's pushed alert; text feed ≈ Plague Inc./Democracy 4's compositional or narrative severity; a robot's animation or office lighting ≈ Oxygen Not Included's whole-scene color wash, ⚠️ snippet-sourced) — the trade-off is between using one channel consistently (simpler, more legible) versus stacking two or three (richer, but closer to the alert-fatigue failure mode the UX literature and Chirper's fate both warn against).
- **Queueing up to three pending cards (base two plus `pooling`'s bypass) is closest to Factorio's and RimWorld's transient/persistent split, not CK3's outliner.** Because Game Night's deferred-warning state is explicitly not addressable and has no feed post, the design question is how (or whether) to signal to the player that something is queued-but-invisible at all — Factorio's approach (a distinct, mutable icon per alert type, individually mutable) and CK3's approach (an outliner the player can open on demand, ⚠️ mechanics not independently verified) represent two different answers to "should the player know a third thing is waiting," with different cost in screen real estate and different fit with the owner's stated preference for keeping the office on screen rather than adding panels.
- **The card dialog itself is already spec'd as a full centered modal (a GDT-style dialog), which is a deliberate exception to the owner's general in-world preference.** The design-history note found that the owner consistently picks options that keep the office visible and put information *in* the world (the phone, the robot) over full-screen panels — but event cards are explicitly specified as centered dialogs reusing the existing generic `dialog()` component, which is itself consistent with how every surveyed game in this report handles the *decision* moment (FTL's text box, CK3's portrait window, GDT's popup) even when its *warning* layer stays diegetic (Reigns' bars, Plague Inc.'s ticker, Frostpunk's crisis pop-up before the deliberate Book-of-Laws menu). The trade-off worth carrying into a design session is not "modal vs. diegetic" for the card itself — that appears settled by both precedent and spec — but how the transition from a diegetic warning (phone buzz, robot bubble, advisor bang-mark) into that modal card is staged, since none of the surveyed games' warning-to-card transitions were found fully documented at the interaction-animation level in this research pass.
- **Backers/opposers chips and the "which choice is the default" question have no direct precedent in the surveyed games**, since none of them expose a card's fallback/auto-resolve choice to the player before the deadline hits (CK3 auto-selects silently; Frostpunk simply ends the run). Game Night's plan already requires showing which advisors back or oppose each choice via check/strikethrough (never color alone) — this is a genuinely novel-to-this-research combination, not a pattern borrowed from elsewhere, and is flagged here as an area with no external design reference to check against, rather than a trade-off between two documented options.
