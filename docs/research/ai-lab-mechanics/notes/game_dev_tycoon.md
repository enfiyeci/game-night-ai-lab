# Game Dev Tycoon (Greenheart Games, 2012/2013) — Complete Mechanics Inventory

Scope note: findings below draw heavily on the Game Dev Tycoon Fandom wiki's reverse-engineered
algorithm pages. These pages are explicitly community reverse-engineering of the game's code
(decompiled/observed behavior), not official developer documentation, and several are tagged by
the wiki itself as version-specific ("applies partially or entirely to version 1.3.9" / "2.0.00")
and possibly outdated for the current release. All formulas and numeric tables below are marked
as **community estimates** unless stated otherwise. Official facts (release dates, Metacritic
scores, the piracy stunt) are sourced separately and marked as such.

## Game creation: topic, genre, platform, audience, size, engine — and their fit scores

### Takeaway
Every new game is defined by up to six choices — topic, one or two genres, platform(s),
target audience, size (Small/Medium/Large/AAA), and a custom engine with selectable feature
modules — and the game scores three independent 3x3-ish compatibility tables (Topic×Genre,
Platform×Genre, Topic×Audience) that feed multiplicatively into the final review-score formula.
A "Great Combo" (value = 1.0 exactly) is the ceiling for topic/genre fit; a "Strange Combo"
(value = 0.6 exactly) is the floor, and multi-genre games weight the first genre twice as heavily
as the second (2:1).

### Cited Findings
- The reverse-engineered top-level formula is `Game_score = Design_and_Tech * Quality * Platform_x_Genre * Topic_x_Audience * Bug_Ratio * Trend_Factor` — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- For multi-genre titles, every combination table (Topic/Genre, Platform/Genre, etc.) is computed as `2/3 * Genre1_value + 1/3 * Genre2_value` — i.e., the primary genre counts twice as much as the secondary — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- "A 'Great Combo' is the strongest topic-to-genre fit... The only way to get a 'Great Combo' for multi-genre games is to use two genres that when used on their own with the chosen topic result in a 'Great Combo'" — [Best Combos in Game Dev Tycoon, Attack of the Fanboy](https://attackofthefanboy.com/guides/best-combos-in-game-dev-tycoon-genre-topic-audience/)
- Topic/Genre combination values in the raw data table range only across a small discrete set (0.6, 0.7, 0.8, 0.9, 1.0); exactly 1.0 is defined as a "Great Combination" and exactly 0.6 as a "Strange combination" (values ≤0.6 trigger the "Strange combination" message) — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Full Topic×Genre table (Action/Adventure/RPG/Simulation/Strategy/Casual) covers 62 topics (Abstract, Airplane, Aliens, Alternate History, Assassin, Business, City, Colonization, Comedy, Construction, Cooking, Crime, Cyberpunk, Dance, Detective, Disasters, Dungeon, Dystopian, Evolution, Expedition, Extreme Sports, Fantasy, Farming, Fashion, Game Dev, Government, Hacking, History, Horror, Hospital, Hunting, Law, Life, Mad Science, Martial Arts, Medieval, Military, Movies, Music, Mystery, Mythology, Ninja, Pirate, Post-Apocalyptic, Prison, Racing, Romance, Rhythm, School, Sci-Fi, Space, Sports, Spy, Superheroes, Surgery, Technology, Thief, Time Travel, Transport, UFO, Vampire, Virtual Pet, Vocabulary, Werewolf, Wild West, Zombies), each scored 0.6–1.0 per genre. Example Great Combos (=1.0): Fantasy/RPG, Fantasy/Action, Sci-Fi/RPG, Sci-Fi/Simulation, Sci-Fi/Strategy, Medieval/RPG, Dungeon/RPG, Superheroes/RPG-adjacent (0.9), Space/Simulation, Space/Strategy — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Platform×Genre table gives each of the ~28 in-game consoles/PC a 0–1 fit score per genre (e.g., PC: Action 0.9, Adventure 1.0, RPG 0.9, Simulation 1.0, Strategy 1.0, Casual 0.6) — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Topic×Audience table (Young/Everyone/Mature) covers the same ~62 topics, e.g., Fantasy and Superheroes score 1.0 across all three audiences, while Fashion scores Young 1.0 / Everyone 0.8 / Mature 0.6 — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- A separate Platform×Audience table exists but "does not influence ratings, only sales" — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Only after the score/target ratio (`u`) is computed does a real penalty apply for bad fit (added in v1.44, not in earlier versions): if `u >= 0.6` and either the Topic/Genre or Topic/Audience factor is `<= 0.7`, the player "loses half your score above 6" (`u = 0.6 + (u-0.6)/2`); if `u >= 0.7`, the score is further multiplied by any Platform/Genre value `<= 0.8` for multi-platform releases — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Custom engines are built from selectable "features" (graphics engines from Text-Based up through 3D Graphics V7, sound, controls, etc.), each with a discrete Tech Level (Text Based=0, 2D V1=1, 2D V2/V3=2, 2D V4/V5=3, 3D V1=1 ... 3D V7=7) that averages with the target platform's own Tech Level to produce the engine's effective Tech Level, which in turn drives "Engine Base Points" via a lookup table (index 0→2 points, 1→5, 2→7, 3→10, 4→15, 5→20, 6→30, 7→40, with linear interpolation between whole levels) — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- Community strategy guidance: "To get maximal Engine Base Points use only 1 Graphic Feature in Engine" — adding more features into one engine dilutes the per-feature efficiency — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- Game size (Small/Medium/Large/AAA) sets an "Optimal Team Size" (1/2/3/6 members per the Tech/Design points algorithm, or 1/3/5/6 per the separate Size Constants table — the wiki's two tables disagree slightly, flagged below) and a "Game Size Factor" (1 / 1 / 0.7 / 0.4) that throttles how efficiently features convert into bonus points as team size scales up — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm); [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Platform tech levels run from PC (none/0) and Govodore 64 (1) up through late-game consoles like mBox Next / PlaySystem 5 (7) — a full 28-entry lookup table of parody consoles maps directly onto real console generations (Atari→PS5 era) — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- A "New combination Factor" doubles Research Point generation (factor of 2 vs 1) the first time a given Genre+Topic pairing is developed, incentivizing trying new combos rather than only replaying a known-good one purely for research income (though not for review score, where repeating the same combo as your last release is explicitly penalized — see Economic pressure section) — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- When a Custom Console (player-built hardware) is created, its own internal Genre-fit and Audience-fit values are not fixed but derived from the player's own release history: genres are tallied (primary genre +1.0, secondary genre +0.5 to the tally), sorted, and assigned fixed slots [1, 1, 0.9, 0.8, 0.8, 0.7]; audiences are tallied and assigned [1, 0.9, 0.8] — meaning a custom console is automatically "great" for whatever genres/audiences the studio has favored historically — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)

### Inferences
- Because Topic/Genre/Audience tables only ever take five discrete values (0.6/0.7/0.8/0.9/1.0), the "creative" combinatorics of the game are really a lookup-table puzzle dressed as creative choice — a design pattern worth deliberately reproducing or deliberately subverting in a re-theme.
- The v1.44 change (penalizing bad fit only above a score threshold, and only halving the *excess* above 6, not the whole score) suggests the original designers wanted bad-fit games to still be sellable/playable at a mediocre level rather than catastrophically failing — a "soft ceiling," not a "hard floor," design choice.
- The custom-console mechanic effectively rewards specialization: a studio that has stuck to 1–2 genres for its whole history gets an console that is automatically near-ideal for exactly those genres, reinforcing path dependency.

### Gaps
- The wiki's Size Constants table (Optimal team size: Small 1, Medium 3, Large 5, AAA 6) conflicts with the Tech/Design Points Generation Algorithm page's table (Small 1, Medium 2, Large 3, AAA 6) for "Optimal Team Size" — this is a documented cross-page inconsistency in the wiki itself (possibly reflecting different game versions), not resolved by any single source found. ⚠️ Flagged as an unresolved contradiction between two community-sourced tables rather than a verified fact.
- No official topic/genre/audience table was found published by Greenheart Games itself; all numeric values are wiki reverse-engineering.

## Development phases: sliders, ideal design/tech ratios, points and bug accumulation, staff effects

### Takeaway
Development runs through three fixed slider "phases" (Engine/Gameplay/Story-Quests → Dialogues/Level-Design/AI → World-Design/Graphics/Sound), each genre has a published "Development Focus" importance weight (0.6–1.0) per field and a fixed optimal Tech/Design point ratio, and the underlying point-generation math is a large per-staff-member formula driven by staff skill stats, "quality factor," workload/utilization, engine tech level, and selected engine features — with bugs spawned as a side effect of the same per-point roll that spawns Tech/Design points.

### Cited Findings
- The three slider phases are fixed: Phase 1 = Engine, Gameplay, Story/Quests; Phase 2 = Dialogues, Level Design, AI; Phase 3 = World Design, Graphics, Sound — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- Optimal Tech/Design ratio per genre (community table): Action 1.8 (64% Tech/36% Design), Adventure 0.4 (29% T/71% D), RPG 0.6 (37.5% T/62.5% D), Simulation 1.6 (61.5% T/38.5% D), Strategy 1.4 (58.3% T/41.7% D), Casual 0.5 (33.3% T/66.7% D) — with a tolerance "Range of Optimal" band around each (e.g., Action: 1.44–2.4) inside which review penalties are avoided — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Development Focus importance table (0.6 low – 1.0 high) per field per genre, e.g., Adventure: Engine 0.7, Gameplay 0.8, Story/Quests 1.0, Dialogues 1.0, Level Design 0.8, AI 0.7, World Design 1.0, Graphic 0.9, Sound 0.8; RPG: Gameplay 0.9, Story/Quests 1.0, Dialogues 1.0, Level Design 0.9, World Design 1.0, Graphic 0.9; Action: Engine 1.0, Gameplay 0.9, AI 1.0, Graphic 1.0 — full 6-genre × 9-field table available — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3)
- Each of the 9 fields also has a fixed Tech/Design "weight" independent of genre — this determines how a field's raw effort converts to Tech vs Design points: Dialogues 90% Design/10% Tech, Gameplay 80/20 Design-heavy, Story/Quests 80/20 Design-heavy, World Design 60/40 Design, Sound 60/40 Design, Graphics 50/50, Level Design 40/60 Tech-heavy, Engine 20/80 Tech-heavy, AI 20/80 Tech-heavy — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide); matching table also at [Raw Data for Review Algorithm/1.4.3](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3) ("Development Weight for Tech and Design Ratios")
- Community analysis: summed across all 9 fields, the total is 500 Design-weight vs 400 Tech-weight, meaning "the whole balance is skewered in Design's favor" — it's structurally easier to hit a Design-leaning ratio than a Tech-leaning one — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- The balance-miss penalty formula (community-derived) is asymmetric: `Delta = (Design * Ideal_Tech_to_Design_Bal - Tech) / max(Design, Tech)`, and the guide walks through a worked example showing that "for a tech-heavy game the margin for error is twice as small" as for an equivalent design-heavy game — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- Resulting genre "attractiveness" ranking by achievable balance error (community table): RPG (0% delta, easiest), Adventure (2.9%), Casual (7.9%), Simulation (9.6%), Strategy (9.6%), Action (23.8%, hardest to balance) — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- Multi-genre combos can push the target balance ratio very close to 1.0 (easiest possible), e.g., Simulation/Adventure or Strategy/Adventure reach ~1.02 — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- In the review-score quality factor, the Tech/Design balance is only checked at all if `Tech + Design >= 30`; the check computes `t = (D*R - T)/max(T,D)` (R = optimal ratio); `|t| <= 0.25` gives +0.1 quality and a "good balance" message, `|t| > 0.50` gives -0.1 quality and a "bad balance" message — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- "Design decisions" scoring (per phase, based on the *time-allocation bar*, not the slider itself): spending >40% of a phase on a field with importance ≥0.9 twice or more gives +0.2 quality with a positive message; once gives +0.1; never gives -0.15 (×2 for MMOs). Spending >40% on a field with importance <0.8 is punished (-0.1 to -0.2, ×2 for MMOs); spending <20% on a field with importance ≥0.9 gives -0.15 per occurrence — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- The per-staff point-generation algorithm (community reverse-engineering) computes, for every staff member and every "mission" (slider field) they're responsible for: a "Staff Utilization" term (their effective workload vs. an ideal, clamped ±1) that penalizes both overloading and under-using a staff member (`1 - 0.75*utilization` if overloaded, `1 - 0.25*|utilization|` if underused); a "Current Quality Factor" derived from staff level (`0.2 + Level/5`, capped and softened above 1.0) plus a temporary "Manager Bonus" (+0.3/+0.2/+0.1 for manager levels 1–3); and a "T/D Skill Focus" (staff's relevant skill stat ÷ 500) — all multiplied together with the mission's engine/feature bonus to yield raw Tech or Design points, which are then spawned individually, each with some probability of instead becoming a Bug Point — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- Bug-spawn probability ("Spawn Factor" for a point to become Tech/Design rather than a bug) ranges from 94% success (6% bug chance) for a max-quality Level-4+ staffer, down to 69% success (31% bug chance) for a Level-1 employee, plus an independent flat 5% chance for a random extra bug point regardless — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- "Boosting" staff ("On Fire" state) adds a 25–50% chance (scaling with trained Boost Level 0–3) of spawning an *extra* Tech/Design/Research point on top of the normal roll — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- The final review-score bug penalty is `r = 1 - (0.8 * clamp[(bugs*100/(Tech+Design)), 0, 100] / 100)`, i.e., bug ratio can reduce score by up to 80%, scaled by how dense the bugs are relative to total points; `r <= 0.6` triggers "Riddled with bugs," `r < 0.9` triggers "Too many bugs" — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Staff attributes and their game effects: Technology (raises Tech-bubble output), Design (raises Design-bubble output), Speed (raises bug-fixing rate and vacation-recovery/re-onboarding speed), Research (raises Research-bubble output), Level (staff level up, unlocking specialization at thresholds) — [Staff, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Staff)
- Specialization/"Expert" status requires a staff member's Tech or Design skill to reach `900 * that field's Development Weight` (e.g., a Dialogues specialist needs Design skill ≥ 900*0.9=810 per the weight table) and, once trained, adds a flat +0.15 to their effective "Staff Responsibility Factor" on assigned missions — [Raw Data for Review Algorithm/1.4.3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Raw_Data_for_Review_Algorithm/1.4.3); [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- Whether a perfect 10/10/10/10 review is even reachable depends on having ≥2 "experts" assigned to fields with importance ≥0.9 for the chosen genre; otherwise the maximum achievable score is capped at 10/10/10/9 — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)

### Inferences
- The Tech/Design point system functions as two parallel resource-accumulation minigames (Design and Tech) whose *ratio*, not their absolute size, is what's graded — meaning raw grind (more staff, more time) helps less than correctly proportioned effort. This is the game's main lever against "just throw more resources at it" optimization.
- Bugs are not a separate axis to minimize outright; they are a tunable trade-off against release timing (the Success Guide explicitly recommends "leave a calculated number of bugs in on purpose" once truncation/rounding make further bug-fixing pointless), which is a distinctive design choice worth preserving or subverting in a re-theme.

### Gaps
- The exact numeric thresholds for staff "Level up" (how much XP/how many games needed per level, levels 1–5+) were not found in the sources reviewed; only that Level correlates to Quality of Staff at fixed steps (Level 1=0.2 ... Level 5=1.0 per `Level/5`).
- Precise Boost training costs/unlock requirements were not retrieved (only the resulting Boost Factor formula).

## Review score formula, sales, fans, hype, marketing, and G3

### Takeaway
The review score is a single hidden "Game Score" run through a Target-Score comparison (mostly a function of your own historical best score, not an absolute bar), then passed through two randomizing "post-treatment" passes and finally displayed as four separately-randomized reviewer scores with canned messages — meaning the number on screen is deliberately noisier and more self-referential than the underlying deterministic Game Score. Sales/fans/hype are driven by review scores, marketing campaign spend, and the annual G3 trade-show event, whose payoff scales with existing fan count.

### Cited Findings
- Game Score formula (final, v1.44): `g = (m + m*q) * p * o * r * w * t`, where `m = (Design+Tech)/(2*Multiplier2)`, `q` = quality factor, `p` = Platform/Genre value, `o` = Topic/Audience value, `r` = bug ratio, `w` = platform tech difference (multi-platform only), `t` = trend factor — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Review score is then `S = [10*g/tgs] * x/10` where `tgs` = Target Game Score and `x` = the "Technical Expertise" cap factor, clamped 1–10 — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Target Game Score (TGS) tracks the player's own history: `TGS = TopScore + TopScoreDelta * YearModifier` (or 20 if no top score set yet); YearModifier = 1.15 before year 6, 1.2 between years 6–23, 1.1 after year 23. TopScoreDelta is capped so it can't exceed 20% of TopScore (outside the garage) — meaning a player who never beats their own best by more than ~12–13% keeps facing a fairly stable, self-set bar, while a huge one-time spike in quality permanently raises the bar by up to 20% — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4); community-simplified restatement at [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide) ("as long as you never increase your Game Score by more than 12% than that of your previous best result, you will keep having a Target_Score of about 112% of your Top_Score")
- "Technical Expertise" (x) further caps the maximum possible score independent of Game Score: Small games below the basement / Medium games with <100K fans / games before size research all cap at 9; Large games cap at `10 - clamp(3-TechLevel, 0, 3)`; AAA games cap at `10 - clamp(5-TechLevel,0,3) - 0.6*clamp(3-ExpertCount,0,3)` — meaning graphics tech level and assigned specialists directly gate the ceiling for big games — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- "Various checks" apply flat penalties/bonuses to the quality factor before scoring: same Topic/Genre/2nd-Genre combo as your immediately previous release: −0.4; sequel/expansion released <40 weeks after its predecessor: −0.4; sequel using the *same* engine as predecessor: −0.1; sequel using a *better* engine: +0.2; MMO with Topic/Genre combo <1: −0.15 — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Trend factor: hitting a Genre/New-Topic/Audience trend gives ×1.2, missing gives ×1.0; for the special "Strange Combos" trend the multiplier is inverted relative to fit quality — a "Great Combo" (topic/genre=1) actually gets penalized to ×0.85, while a genuinely "strange" combo (<0.8 fit) is rewarded up to ×1.4 — i.e., the game explicitly rewards makers for chasing an unusual pairing during that trend window — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Post-treatment "First Pass": if the pre-adjusted score S ≥ 9 and either quality factor q < 1.1 (80% chance it triggers) or a staff member with very little career "contribution" was assigned (near-certain on their first assigned game), the score gets forcibly re-rolled down into either [8.45, 9.1] (75% chance) or [9, 9.25] (25% chance) — meaning a brand-new hire can single-handedly cap a would-be 9–10 game down near 8–9 the first (and sometimes second) time they're staffed, by design or by an acknowledged bug in the "contribution" counter — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Post-treatment "Second Pass" (active only before year 4, and only if fewer than 2 "high score" games have been published): a would-be 10 is knocked down to a random [8.5, 8.95]; a 9–10 is knocked down by [1.05, 1.25]; an 8.5–9 is knocked down by [0.4, 0.6] and loses "high score" status; but the *third* game that qualifies as a high score is forced to exactly 10 — an explicit early-game training-wheels mechanic that guarantees an early "perfect game" moment — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Final display step: one underlying score generates four separately displayed reviewer scores; each is nudged by a random offset (0: 50%, ±1: 25%/25% normally, with an extra ±2 tail of 1.25% each when the base score is 5 or 6), then clamped 1–10, with matching canned "good/bad/standard" messages drawn per score band — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- G3 (parody of E3) occurs annually at Month 6, Week 2 (booth purchased at start of Month 5, Week 1); booth tiers cost $80K (Small), $500K (Medium), $1.5M (Large); attendance and a 1–100 ranking score scale with the studio's existing fan count (and, minorly, booth size) — [G3, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/G3); consistent with community guidance that G3 provides the single cheapest/biggest hype boost of the year and studios should always have a game in development when it triggers — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- Marketing campaign strategy (community, not official numbers): a 500K campaign at the start of Stage 2 of development, occasional 50K "top-up" campaigns, and a "Special AAA marketing" option that the guide author calls not worth the cost, plus a 2M campaign as the AAA-scale equivalent of the 500K campaign — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- Medium games are review-capped at 9 until the studio reaches 100,000 fans — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)

### Inferences
- The Target-Score-tracks-your-own-history design (rather than a fixed absolute bar) is the single biggest anti-optimization lever in the whole game: it converts "make a good game" into "make a game modestly better than your own last great game," which mathematically guarantees an escalating treadmill regardless of genre or platform choice.
- The four-reviewer randomization step exists purely for game-feel/presentation — it deliberately reintroduces noise and "personality" (four differing opinions) on top of an already-deterministic score, which is likely central to why reveal moments feel more like "real critics" than a single number would.

### Gaps
- No official confirmation from Greenheart Games of any of the review-score internals above was found; everything is wiki/community reverse-engineering, explicitly labeled by the wiki as version-tagged and possibly stale for the current release.
- Exact sales-to-review-score conversion curve (how many units per review point, fan growth per unit sold) was not found in a citable, load-bearing form beyond qualitative community guidance; this is a gap.

## Research and progression: points, engine, features, training, hiring, offices, contracts, hardware/R&D labs, MMOs, self-publishing, endgame

### Takeaway
Progression is gated by a single "Research Points" currency earned passively during development (with a 2x bonus for trying a brand-new topic/genre combo) or from R&D Lab budget once unlocked, spent on an ever-growing tech tree (graphics versions, new topics/genres, target audiences, Large/AAA game sizes, MMO support, a custom Hardware Lab/console, and late-game systems like engine licensing and AAA marketing), while staff progression (hiring, training, specialization, vacations) and office upgrades (which unlock hiring, R&D, and Hardware Lab access) form a second, parallel gate.

### Cited Findings
- Research Points generation formula (community): `RP = 2 * NewCombinationFactor * (1 + rand(0,0.1)) * (MissionPctOfPhase*3/100) * SizeMultiplier2 * ResearchSkillFocus`, where `NewCombinationFactor` = 2 for a first-time Topic/Genre pairing (else 1), and `SizeMultiplier2` scales with game size (Small 1, Medium 1.2, Large 1.4, AAA 1.8) — generated only during the Development stage, not Preparation or Bug-Fixing — [Tech and Design Points Generation Algorithm, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Tech_and_Design_Points_Generation_Algorithm)
- "To gain research points, get an R&D lab or invest in training one of your people in research... Contracts also give research points" — [Research Points community summary via search results](https://gamedevtycoon.fandom.com/wiki/Research_Tips)
- Custom engine creation is available any time from the very first office ("garage"); the community strategy is to rebuild the engine after nearly every game and especially immediately after any graphics-tier research unlock — [Research Tips, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Research_Tips)
- Hiring becomes available at the second office, gated behind training the player-character in "Staff Management" first; the hiring UI offers a budget slider (more budget = more/better candidates found, not simply "better" — office level also matters) and three filter presets: Complex Algorithms (Tech-focused candidates), Game Demo (balanced Design+Tech), Showreel (Design-focused) — [Staff, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Staff); [Research Tips, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Research_Tips)

- R&D Lab (unlocked at the fourth office / "technology park") converts an allocated monthly budget into R&D points toward whatever project is active (a console, or generic research if nothing is active); Research Areas and costs: Internet 500 pts (unlocks MMO & "Codename: GRID" research), Hardware 800 pts (unlocks the Hardware Lab / own console development), MMO (unlocks the MMO engine part), Codename: GRID (raises PC market share + passive monthly income), Convention 500 pts (a repeatable personal trade-show alternative to G3, available once fans exceed 1,000,000 or by Year 23), AAA/3D Graphics V6 (requires 3D V5 at level 4 and an average large-game score above 9.25), 3D Graphics V7 (requires V6 at level 4 — the final graphics tier), License Game Engines (unlocked after 10 custom engines built; adds a sellable "Software Development Kit" monthly-income feature), Marketing Campaign 1000 pts (a massive campaign specifically for an in-development AAA game) — [R&D Lab, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/R%26D_Lab)
- Community path to unlock R&D/Hardware Labs: release 3 games, train your two most experienced staff to 700+ in Technology and Design respectively (specializing each), keep releasing games until reaching roughly $20M cash, at which point a prompt offers the R&D Lab for $5M (or wait); inside R&D, running the "Hardware opportunities" project (with a Technology specialist) then triggers a further prompt to buy the Hardware Lab for another $5M — [Research Tips, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Research_Tips)
- MMO development requires researching MMO support in the R&D Lab and then building a dedicated MMO Engine (a normal engine cannot make an MMO); community guidance recommends never releasing an MMO expansion immediately after launch and never releasing multiple MMOs back-to-back — [Research Tips, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Research_Tips); [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)
- "If you do an MMO, you can break the game even further — MMO is basically a linearly increasing income/expense, so if you don't watch it, you go bankrupt but if you do release expansions every now and then, you start to get insane amount of money after several expansions. - AAA game development requires at minimum 3D Graphics V6 (community: "at Tech Level 5 or higher") and at least 3 assigned specialists in fields the chosen genre marks important; the guide ranks specialist priority as Graphics (used everywhere) > Level Design & Gameplay > Sound & AI > Engine & Dialogues > Story/Quests & World Design (least useful) — [Research Tips, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Research_Tips); [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide)

- Training options include a category-specific "Staff Welcome Training" (mandatory-in-practice for new hires), stat-specific training (Design/Tech/Speed/Research), and a "Boost" training track (community verdict: "Do not train Boost. - The endgame/late progression includes: player-developed custom consoles via the Hardware Lab (community: "probably need ~200M to make the best one," maximize Q&A budget and feature count, and budget ~$500K/month post-launch for support), engine licensing income, MMO expansions, and the "Convention" as a self-run alternative to G3 once fan count is very high — [Success Guide, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Success_Guide); [R&D Lab, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/R%26D_Lab)

### Inferences
- The dual-currency structure (Research Points for the tech tree, cash for hiring/marketing/labs) plus the staff-training loop creates two interleaved progression tracks that must be balanced together — a re-theme should preserve this "two currencies, one bottleneck at a time" structure rather than collapsing it to a single resource.
- The R&D Lab/Hardware Lab path is explicitly the "own the platform" endgame fantasy (going from software vendor to platform owner), directly analogous to a lab building its own chips/compute stack rather than renting cloud GPUs — a strong, almost literal transfer candidate.

## Economic pressure: costs, bankruptcy, and anti-optimization design

### Takeaway
The game enforces a hard bankruptcy game-over at –$200K debt (after a bank bailout), and layers at least three explicit anti-repetition/anti-optimization mechanisms on top of the score formula: a same-combo penalty, a rising personal-best bar (Target Score), and post-processing "first/second pass" randomization that specifically punishes over-relying on brand-new hires or on a too-early quality spike — while community sentiment is split on whether these pressures feel like meaningful strategy or like arbitrary "slot machine" punishment.

### Cited Findings
- "Bankruptcy occurs when a company is too far in debt and have recently been bailed out by the bank... The game classifies debt as more than 200K [-$200K+]... This typically represents a game over, and forces you to either load a Savegame or restart the level or start a new game." — [Bankruptcy, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Bankruptcy)
- The bankruptcy screen's in-fiction flavor text has the studio bought out by a rival ("Electronic Mass Productions/Stygnya... acquired the rights to all of [COMPANY NAME]'s previously released titles") — a Wikipedia-parody ending rather than a soft restart — [Bankruptcy, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Bankruptcy)
- Anti-repetition levers baked into the review formula itself: −0.4 quality penalty for repeating the exact same Topic/Genre/2nd-genre combo as the immediately previous release; −0.4 for a sequel/expansion released under 40 weeks after its predecessor; the Target Score mechanism (see Review section) that makes the bar rise with the player's own recent best, capped at a 20% jump per release outside the garage — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- The "First Pass" post-treatment specifically detects and suppresses scores that would otherwise be ≥9 when a low-experience staff member was assigned to the project, functioning as an implicit tax against "buy your way to a great game via one genius/one big roster" strategies — [Review Algorithm/1.4.4, Game Dev Tycoon Wiki](https://gamedevtycoon.fandom.com/wiki/Review_Algorithm/1.4.4)
- Player-reported friction (Steam Community discussions, aggregated by search, not individually opened in full — see coverage statement): "monthly payments growing too much due to employment level ups," a felt need for "more late-game options when running out of money," and complaints that the bailout system is ineffective late-game — [Steam Community discussions on bankruptcy, aggregated via search](https://steamcommunity.com/app/239820/discussions/0/864977564336994349/)
- A critical review (Gamecritics.com, 3/10) states the reviewer discovered "profitability required upwards of 20 games per year," calling this "so incredibly taxing and boring" that they gave up, and separately concluded that despite following tutorials on engine upgrades, staff training, and market trends, "the success or failure of a game seems to be completely random" — a direct critique that the anti-optimization randomization reads to players as arbitrariness rather than strategy — [Game Dev Tycoon Review, Gamecritics.com](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/)
- The same review notes that in practice, success came only from "repeatedly making the same game types," which the reviewer says undermines the game's own stated advice against repetition — i.e., the anti-repetition penalty is real in the formula but was, in this critic's experience, still weaker than the benefit of sticking to a known-good genre — [Game Dev Tycoon Review, Gamecritics.com](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/)

### Inferences
- The bankruptcy threshold is a simple flat debt ceiling (–$200K) rather than a ratio of debt-to-revenue or debt-to-cash-flow, meaning the felt difficulty of "going bankrupt" scales down in relative terms as the studio's overall cash flow grows — early-game bankruptcy risk (where $200K is a large fraction of total assets) is structurally much scarier than late-game risk, which likely explains why player complaints skew toward "getting started" being the hardest financial period, matching a classic tycoon-game "early-game death spiral" pattern.
- The gap between designer intent (repetition is explicitly penalized in the formula) and critic experience (repetition still felt like the winning strategy) is itself a useful design lesson for a re-theme: an anti-optimization penalty that's smaller than the payoff of ignoring it will not actually stop players from ignoring it.

### Gaps
- ⚠️ The Steam Community "bankruptcy" and "grindy" discussion threads were only read via WebSearch's synthesized snippets, not opened and read to the end individually — the specific discussion pages (e.g., steamcommunity.com/app/239820/discussions/0/864977564336994349/ and sibling threads) were not fetched in full in this session. The quotes/characterizations above reflect the search tool's own summarization of those threads, not a first-hand full read.
- No official Greenheart statement on intended bankruptcy-avoidance design or the "difficulty curve" was found.

## Game-feel: bubbles, review reveal, "one more game," and common criticisms

### Takeaway
Reviewers consistently credit two feel-moments — the satisfying visual/audio "ding" and floating point-bubbles during development, and the multi-reviewer score-reveal screen — as the emotional core of the loop, while the most common criticism across a positive-mobile/mixed-PC reception split is that the underlying success math feels opaque and, particularly in the late game, that optimal play degenerates into repetitive, high-volume grinding rather than deepening strategy.
### Cited Findings
- "the satisfying 'ding' that sounds when a game is complete" is called out as a genuine pleasure, and the core loop of "selecting genres, mechanics, platforms, and watching results unfold" is cited as the game's initial appeal — [Game Dev Tycoon Review, Gamecritics.com](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/)
- The same review criticizes the feedback the game actually gives as vague ("Racing and Action are a great match" with no deeper guidance) and says review-score explanations are reduced to short canned quips ("Fun," "Falls a bit short"), "making success feel arbitrary" — [Game Dev Tycoon Review, Gamecritics.com](https://gamecritics.com/tayo-stalnaker/game-dev-tycoon-review/)
- GameGrin's review is quoted (via search synthesis) as saying the game has "that draw of 'one more game' to it, just in this case you're developing one more game in the hopes of a blockbuster hit" — [Game Dev Tycoon Review, GameGrin, cited via search](https://www.gamegrin.com/reviews/game-dev-tycoon-review/)
- Aggregate critical reception (Wikipedia, English-language summary): Windows/PC version scored 68/100 on Metacritic ("mixed"); iOS version scored 89/100 ("positive"), with TouchArcade giving it a perfect 5/5; Nintendo Switch version scored 81/100 ("positive") — [Game Dev Tycoon, Wikipedia](https://en.wikipedia.org/wiki/Game_Dev_Tycoon)
- The PC-vs-mobile reception gap (68 vs 89/81) is itself a notable, citable data point: the same core loop reads very differently depending on platform/session-length context — [Game Dev Tycoon, Wikipedia](https://en.wikipedia.org/wiki/Game_Dev_Tycoon)

### Inferences
- The reception split (mixed on PC, strongly positive on mobile) suggests the loop's "bubbles + reveal + one more game" hook reads best in short, frequent sessions, and that the parts critics dislike (grindy late game, opaque math) are exactly the parts that matter most in a long, single-sitting PC session — a signal for how much depth vs. how much "snackability" a re-themed version should aim for depending on target platform.
- Both positive and negative reviews converge on the same mechanical description (bubbles/ding as delight, opaque scoring as friction) — meaning these are stable, load-bearing "feel" elements the game is known for rather than one critic's idiosyncratic take.

## Transfer notes: reframing Game Dev Tycoon mechanics as an "AI lab" game

| Game Dev Tycoon mechanic | AI-lab transfer idea | Transfers well / needs rework / drop |
|---|---|---|
| Topic (Fantasy, Sci-Fi, Zombies, ...) | Application domain (coding, customer support, robotics, drug discovery, creative writing) | Transfers well — same role: a flavor axis with fixed fit-to-genre scores |
| Genre (Action, RPG, Strategy, Simulation, Adventure, Casual) | Model type / product category (chatbot assistant, agentic coding tool, image generator, recommendation engine, autonomous agent, copilot) | Transfers well — genres already function as "product category," directly analogous |
| Platform (PC, consoles by console generation) | Deployment surface / compute substrate (own datacenter GPUs, a cloud provider's TPUs, on-device/edge, a specific hardware generation like H100 vs B200) | Transfers well, with rework — Tech Level per platform maps neatly onto "compute generation," but needs its own escalating ladder (roughly one new "console gen" per couple of years mirrors real accelerator generations) |
| Target Audience (Young/Everyone/Mature) | User segment (consumer, prosumer/developer, enterprise/regulated) | Transfers well |
| Topic×Genre / Platform×Genre / Audience×Topic fit tables | Domain-fit tables: which model type suits which application, which deployment fits which model type, which segment suits which domain | Transfers well — same discrete lookup-table structure works, just needs new values curated for plausibility (e.g., "agentic coding" + "enterprise" = great combo) |
| Engine + selectable graphics/feature modules (2D→3D V1-V7) | Base/foundation model + architecture choices (attention variants, MoE, retrieval, tool-use modules), with an escalating "generation" ladder (GPT-2-era → GPT-5-era equivalent) | Transfers well — "build a new engine after every graphics-tier unlock" maps directly onto "retrain/upgrade your base model after every architecture breakthrough" |
| Design points / Tech points / genre-specific ideal ratio | Alignment & product-quality points vs. raw capability/benchmark points, with a genre-specific ideal ratio (a coding agent skews capability-heavy, a consumer companion app skews alignment/UX-heavy) | Transfers well — this is the single most reusable mechanic; the design/tech tension maps almost one-to-one onto "capability vs. safety/UX polish" |
| Bugs (spawned as a side effect of point generation, penalize score by density) | Hallucinations / safety incidents / jailbreaks, spawned as a side-effect of rushed capability gains, penalizing the "review" (benchmark/press) score by density relative to total capability | Transfers well — bugs-as-emergent-byproduct-of-rushed-work is exactly the hallucination narrative |
| Review score formula (Game Score vs rising personal-best Target Score, four separately randomized "reviewer" scores) | Model release reception: an internal benchmark score compared against your own lab's rising bar (each release must beat your last flagship by a margin or it "flops"), revealed as several independently-noisy outlets (four benchmark leaderboards, or four review outlets like independent evals/Chatbot Arena/a safety audit/press) | Transfers well conceptually; needs rework of exact numbers, since a lab's "self-referential rising bar" is a strong satirical parallel to real frontier-lab framing ("beat our own last model") |
| Same-combo penalty / sequel-too-soon penalty | Diminishing-returns penalty for shipping another near-identical model too soon after the last one, or an incremental point-release with no architecture change | Transfers well — satirizes real "just scale it up again" release cadences |
| Trend factor (genre/topic/audience/"strange combos" trend, with inverted reward for chasing strangeness) | Hype cycles (agents, reasoning models, multimodal, "world models") that reward riding the current wave, plus a rarer "contrarian bet" trend that rewards an unfashionable architecture choice | Transfers well |
| Technical Expertise cap (graphics tech level + assigned specialists gate the max possible score for Large/AAA games) | Compute scale + specialist researcher headcount gates the max achievable score for frontier-scale models — you cannot out-execute a compute/talent ceiling | Transfers well |
| Staff attributes (Tech, Design, Speed, Research, Level) + specialization | Researcher/engineer skill stats (capability-research skill, safety/alignment skill, engineering speed, "research taste"/publication skill) + specialization (an "interpretability specialist," a "RLHF specialist") | Transfers well |
| Hiring via budget slider + 3 filter presets (Complex Algorithms/Game Demo/Showreel), famous real-industry pun names | Recruiting via a compensation-budget slider + filters (research-focused / engineering-focused / balanced) with easter-egg "famous AI researcher" pun-name hires | Transfers well, including the fun/easter-egg layer |
| Vacations / exhaustion / welcome training | Burnout, onboarding ramp-up for new hires, sabbaticals | Transfers well |
| Research Points + tech tree (topics, genres, audiences, sizes, graphics tiers, MMO support, hardware) | "Research compute/credits" currency spent on a tech tree (new domains, new model types, new user segments, larger training runs, next architecture generation, agentic/tool-use unlock, own silicon) | Transfers well — the two-currency (cash + research points) structure should be preserved as (funding/revenue + compute-and-research-credits) |
| Game size (Small/Medium/Large/AAA) with optimal team size and diminishing size-factor | Model scale tier (small fine-tune, mid-size model, frontier model, "AGI-scale" moonshot) with optimal team size and diminishing coordination efficiency at larger scale | Transfers well — very on-theme (a moonshot AGI project needs many more researchers but each contributes less efficiently, mirroring real "Mythical Man-Month" critiques of huge AI orgs) |
| Publisher contracts vs self-publishing, with fan-count break-even thresholds | Cloud/platform partnership deals (e.g., ship your model via a big platform's API marketplace, sharing revenue) vs self-hosted API, with a user-count/brand-strength break-even threshold | Transfers well |
| R&D Lab (budgeted, converts into research points/console project) | Internal "Frontier Research" division/lab-within-the-lab that converts budget into research credits toward a specific moonshot project (a custom chip, an AGI-scale run) | Transfers well |
| Hardware Lab / building your own console | Building your own chip/accelerator or your own datacenter — the "own the compute stack" endgame fantasy | Transfers well — arguably the single most natural 1:1 mapping in the whole game, since real frontier labs increasingly do pursue custom silicon |
| MMO support + MMO engine + recurring expansion income (and its "linear income/expense, easy to bankrupt if mismanaged" risk profile) | A hosted API product / subscription assistant with recurring compute costs and recurring revenue, where poorly-managed usage growth can bankrupt the lab (expensive inference at scale) if pricing/costs aren't watched, "expansions" = new feature releases/price tiers | Transfers well, and is thematically sharp (compute cost scaling is a real, well-known AI-lab risk) |
| G3 conference (annual trade show, booth-size cost tiers, attendance/hype scaling with fan count) | An annual flagship AI conference (a NeurIPS/DevDay-style event) where a booth/keynote-size purchase converts existing user/follower base into a hype spike for whatever model is in training | Transfers well |
| Marketing campaigns (flat-cost hype injections at specific development milestones) | PR/launch campaigns, high-profile demo videos, "leak" strategies timed to model training milestones | Transfers well |
| Bankruptcy at a flat debt threshold, ending in a rival buyout | Running out of runway/funding, ending in an acquihire by a bigger lab/Big Tech company | Transfers well, and is a sharp, already-familiar real-world AI-industry narrative (compute costs outrunning revenue, forced acquisition) |
| The real-world anti-piracy stunt (a seeded "cracked" build that fictionally bankrupts pirate-players via an in-fiction piracy message) | Not a core game mechanic — a one-off marketing/PR stunt about the real game's own distribution, not something to reproduce inside an AI-lab game's simulated economy | Drop — interesting as design-team lore/inspiration for the studio's brand voice, but not a mechanic to port into the new game itself |
| Post-treatment randomization that suppresses good scores when a fresh, low-experience hire is staffed | A fresh, unproven researcher/engineer contributing noise/instability to a model's flagship release the first time they're staffed on it | Needs rework — the *mechanic's intent* (new hires add risk) is worth keeping, but the specific "silently re-roll the score down" implementation reads to players as arbitrary/opaque (per the Gamecritics review) and a re-theme should make this legible in the UI rather than hidden, to avoid repeating that exact criticism |
| Rising personal-best Target Score (the core anti-plateau mechanic) | Each new model release must beat the lab's own last flagship by a rising margin to count as a "success," modeled transparently as a visible escalating internal bar | Transfers well conceptually, but needs rework for transparency — keep the "you're really competing with your own last best" structure (it's the single sharpest and most re-themeable idea in the whole game) but expose the target number to the player, unlike the original's fully hidden calculation, to avoid the "feels random" criticism |
| Four independently-randomized reviewer scores with canned messages | Four independently-noisy eval sources (a public leaderboard, an independent red-team audit, social-media/"vibes" sentiment, an enterprise-customer satisfaction score) each giving a slightly different verdict on the same release | Transfers well — strong thematic fit for how a real model launch actually gets received across different audiences |
| Grindy late-game ("20 games/year to stay profitable") | Late-game treadmill of shipping frequent minor point-releases/fine-tunes just to keep revenue flowing | Needs rework — this is the loop's most-cited flaw; a re-theme should deliberately design against it (e.g., diminishing grind via passive/idle systems, or explicit high-value "big bet" projects that reward patience) rather than reproduce it uncritically |
